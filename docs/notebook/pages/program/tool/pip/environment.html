虚拟环境与依赖管理

使用对应的 Python 安装包

一台电脑上可能同时安装了多个 Python 解释器。使用 python -m pip 可以让 pip 明确对应到当前的 Python；macOS 或 Linux 上也可以将命令中的 python 换成 python3。 

    python3 --version
    python3 -m pip --version
    python3 -m pip install requests

为项目创建虚拟环境

虚拟环境可以隔离不同项目的依赖。在项目根目录执行： 

    python3 -m venv .venv

macOS 或 Linux 激活环境：

    source .venv/bin/activate

Windows PowerShell 激活环境：

    .venv\Scripts\Activate.ps1

激活后，使用 python 和 python -m pip 就会操作该虚拟环境。完成工作后，可以运行 deactivate 退出。也可以不激活环境，直接调用其中的解释器： 

    .venv/bin/python -m pip install requests

Windows 对应的解释器路径为 .venv\Scripts\python.exe。 通常不应把 .venv 目录提交到版本控制。

记录与安装依赖

项目可以使用 requirements.txt 记录要安装的依赖。例如： 

requests>=2.31,<3
flask==3.0.0

在虚拟环境中安装清单里的依赖：

    python -m pip install -r requirements.txt

pip freeze 可以导出当前环境所有已安装包的确切版本，常用于记录可复现的环境： 

    python -m pip freeze > requirements.txt

freeze 会包含传递依赖和环境中的其他包。长期维护的项目通常需要区分直接依赖与完整环境锁定结果，不要不加检查地把临时环境的所有包都作为项目依赖。

检查依赖状态

检查当前环境中已安装包的依赖关系，并查看可升级的包：

    python -m pip check
    python -m pip list --outdated

pip check 报告缺失或冲突的依赖，但不会自动修复问题。升级包之前，应确认项目代码和其他依赖仍然兼容。

安装本地项目

如果 Python 项目已配置 pyproject.toml，可以在项目根目录以可编辑模式安装。开发过程中修改源代码后，无需反复重新安装： 

    python -m pip install -e .
