BUILD 文件与依赖

BUILD 文件定义目标

BUILD 文件使用 Starlark 语法描述包中的目标。常见目标包括：

  • cc_binary：C/C++ 可执行程序。
  • cc_library：C/C++ 库。
  • cc_test：C/C++ 测试。

一个目标通常通过 srcs 声明源文件、 hdrs 声明公开头文件，并通过 deps 声明它需要的其他目标。目标的名称在同一个包中必须唯一。

包和标签

包是 BUILD 文件所在的目录。假设项目结构如下： 

project/
├── MODULE.bazel
├── BUILD
├── main.cc
└── lib/
    ├── BUILD
    ├── greeter.cc
    └── greeter.h

根目录和 lib/ 分别是一个包。在根目录 BUILD 中，可以用 //lib:greeter 引用 lib/BUILD 中名为 greeter 的目标。同一个包内也可以使用简写 :greeter。

BUILD 文件不会自动把子目录变成同一个包：每个有 BUILD 文件的目录都是独立的包。跨包依赖时，目标还需要允许被其他包访问，例如在 lib/BUILD 中为 greeter 库设置： 

cc_library(
    name = "greeter",
    srcs = ["greeter.cc"],
    hdrs = ["greeter.h"],
    visibility = ["//visibility:public"],
)

然后在根目录 BUILD 的 deps 中声明 //lib:greeter。

声明模块依赖

外部模块依赖由根目录的 MODULE.bazel 管理。使用规则集时，可在这里声明它的名称和版本： 

bazel_dep(
    name = "rules_example",
    version = "1.2.3",
)

上面的名称和版本仅为语法示意，实际使用时应选择 Bazel Central Registry 中存在的模块版本，并按照该规则集的文档在 BUILD 文件中加载和使用规则。模块的传递依赖由 Bzlmod 一并解析。

增加或升级模块依赖后，应检查代码评审中的 MODULE.bazel 变更，并在本地运行相关构建和测试。不要把机器本地的绝对路径作为团队共享依赖。
