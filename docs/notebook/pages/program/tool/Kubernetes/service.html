Service 与 Ingress

Pod 的 IP 会随着重建而变化，所以不能直接用 IP 访问。 Service 提供一个稳定的服务入口， Ingress 则在其上再叠一层按域名和路径分流的七层路由。

Service

先用命令快速体验一下： 

# 把 Deployment 暴露成一个 Service
kubectl expose deployment hello --port=80 --target-port=80

kubectl get services

对应的 YAML 写法： 

apiVersion: v1
kind: Service
metadata:
  name: hello
spec:
  type: ClusterIP
  selector:
    app: hello
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80

Service 通过 selector 找到后端的 Pod，只要 selector 匹配上 Pod 的标签，Service 就会自动把流量负载均衡过去。因此 Pod 扩缩容后，Service 无需任何修改。

port 是 Service 自己监听的端口， targetPort 是容器实际监听的端口。两者可以不同，比如 Service 用 80，容器用 8080。

Service 的四种类型

类型 说明
ClusterIP 默认类型，只能在集群内部访问
NodePort 在每个节点上开一个随机端口（30000-32767），通过节点 IP 访问
LoadBalancer 由云厂商分配外部负载均衡器，最常用
ExternalName 把流量直接转到集群外部的域名，不做任何代理

本地环境用 kind 时，LoadBalancer 类型的外部地址会一直显示 <pending> ，因为本地没有云厂商的负载均衡器。可以直接用 NodePort 访问： 

kubectl expose deployment hello --type=NodePort --port=80
kubectl get svc hello

NAME    TYPE        CLUSTER-IP      EXTERNAL-IP   PORT(S)        AGE
hello   NodePort    10.96.141.52   <none>        80:31234/TCP   20s

然后在浏览器访问 http://localhost:31234 即可。

DNS 解析

集群内每个 Service 都会自动获得一个 DNS 域名，格式是： 

<service-name>.<namespace>.svc.cluster.local

比如同一个命名空间里访问 hello，直接用 hello 就行；跨命名空间则写 hello.demo 。

Ingress

Ingress 在 Service 之上提供基于域名和路径的路由。要使用它，需要集群里已经安装了 Ingress Controller （例如 Nginx Ingress、Traefik 等）。

kind 创建的默认集群不包含 Ingress Controller。可以在安装时指定： kind create cluster --config kind-cluster.yaml 时加入 Ingress 节点，或者事后单独安装。本篇只介绍 Ingress 的配置写法。 
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: hello-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  rules:
    - host: hello.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: hello
                port:
                  number: 80

应用后可以查看状态： 

kubectl apply -f ingress.yaml
kubectl get ingress

NAME            CLASS    HOSTS               ADDRESS     PORTS   AGE
hello-ingress   nginx    hello.example.com   localhost   80      20s
Ingress 只是「路由规则」，真正的转发由 Ingress Controller 完成。如果访问不通，先确认 Ingress Controller 是否已安装并正常运行，再排查规则本身。

给 Ingress 配置域名与路径

一个 Ingress 可以同时配置多个域名，也可以按路径分流到不同的 Service： 

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: multi-ingress
spec:
  rules:
    - host: shop.example.com
      http:
        paths:
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: hello-api
                port:
                  number: 80
    - host: www.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: hello-web
                port:
                  number: 80
pathType 常用两个值： Prefix 表示路径前缀匹配（路径按 / 分段匹配）， Exact 表示完全精确匹配。默认行为容易出坑，建议显式写出来。

HTTPS

在 Ingress 里声明 tls 字段即可启用 HTTPS： 

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: tls-ingress
spec:
  tls:
    - hosts:
        - hello.example.com
      secretName: hello-tls
  rules:
    - host: hello.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: hello
                port:
                  number: 80

其中 hello-tls 是存放证书的 Secret，类型需要为 kubernetes.io/tls ，包含 tls.crt 和 tls.key 两个键。
