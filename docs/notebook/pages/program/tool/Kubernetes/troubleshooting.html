常见问题排查

本篇整理了学习和使用 Kubernetes 时最常遇到的问题，以及对应的排查思路。

排查问题的通用步骤

遇到问题基本都按这个顺序来： 

# 1. 看状态
kubectl get pods

# 2. 看详情和事件（最关键）
kubectl describe pod hello-xxxxx

# 3. 看日志
kubectl logs hello-xxxxx

# 4. 看上一个崩溃实例的日志
kubectl logs hello-xxxxx --previous
describe 输出末尾的 Events 部分几乎能解决 80% 的问题，比如 Failed to pull image 、 OOMKilled 、 Back-off pulling image 等等。

Pod 一直处于 Pending

Pending 表示 Pod 已经被创建但还没被调度到节点上。用 describe 查看事件： 

kubectl describe pod hello-xxxxx

常见原因：

  • 资源不足：节点 CPU/内存不够，或者节点被打了污点（taint）。
  • PVC 未绑定：Pending 的 Pod 一直等不到存储。
  • 节点选择器或亲和性不匹配：Deployment 里写了 nodeSelector，但没有任何节点满足条件。 
# 查看 PVC 状态
kubectl get pvc

ImagePullBackOff / ErrImagePull

镜像拉不下来。依次排查：

  • 镜像名和 tag 是否正确（私有镜像需要正确的 registry 凭证）；
  • 网络是否能访问镜像仓库（集群内可能需要配置代理或镜像加速）；
  • 如果是私有仓库，确认 imagePullSecrets 已配置且 Secret 存在。
# 确认拉取失败的具体错误
kubectl describe pod hello-xxxxx

# 在节点上手动拉取验证
docker pull nginx:alpine

CrashLoopBackOff

容器反复启动又崩溃。先看上一次崩溃的日志： 

kubectl logs hello-xxxxx --previous

常见原因：

  • 启动命令执行失败（配置缺失、依赖的 Secret/ConfigMap 不存在）；
  • 健康检查接口路径写错，livenessProbe 一直失败；
  • 应用启动耗时超过 startupProbe 的容忍时间。
# 看重启次数
kubectl get pods

NAME                        READY   STATUS             RESTARTS   AGE
hello-6d8c9f7b4f-xk2mq     0/1     CrashLoopBackOff   5          3m

OOMKilled

容器内存超出 limit 被杀掉。查看状态和内存设置： 

kubectl describe pod hello-xxxxx
kubectl top pod hello-xxxxx

解决办法是提高 resources.limits.memory ，或排查应用是否存在内存泄漏。

如果状态是 OOMKilled 但应用看起来内存占用不高，可能是被 Node 层面的 OOM 杀掉了，需要查看节点日志（dmesg）。

ImagePullBackOff 之外的拉取正常但 Pod 不 Ready

容器运行了但没进入 Ready 状态，通常是 readinessProbe 没通过。此时 Service 不会把流量转发给它： 

kubectl describe pod hello-xxxxx
kubectl get endpoints hello

确认 Pod 标签和 Service 的 selector 能匹配上，这是最常见的低级错误： 

kubectl get pods --show-labels
kubectl get svc hello -o jsonpath='{.spec.selector}'

kubectl 连不上集群 

# 看看当前到底连的是哪个集群
kubectl config current-context
kubectl cluster-info

# 看看配置里有哪些集群
kubectl config get-contexts

常见情况：

  • 上下文切错了，用 kubectl config use-context 切回来；
  • kind 集群被删了但配置还在，重新创建或清理掉旧上下文；
  • 本地集群需要确认 Docker 正常运行。

资源一直无法创建

apply 时报错，先用 dry-run 看看具体是什么问题： 

# 服务端校验，不实际提交
kubectl apply -f deploy.yaml --dry-run=server

# 对比当前状态和目标状态
kubectl diff -f deploy.yaml

常见报错：

报错 原因
selector does not match template labels Deployment 的 selector 和 Pod 模板标签不匹配
field is immutable 修改了不可变字段（比如 Deployment 的 selector）
already exists 用了 create 而不是 apply
no matches for kind apiVersion 写错，或 CRD 没有安装

滚动更新卡住 

kubectl rollout status deployment/hello
kubectl describe deployment hello

常见原因：

  • 新 Pod 无法通过 readinessProbe；
  • maxUnavailable 设成了 0 且 maxSurge 也不够，导致没有可用的新 Pod；
  • 资源不足，新 Pod 一直 Pending。
回滚比排查更快： kubectl rollout undo deployment/hello 先把服务恢复，再慢慢查原因。

端口占用与访问不通 

# 本地端口转发到 Pod
kubectl port-forward hello-xxxxx 8080:80

# 查看 Service 分配的端口
kubectl get svc hello

# 查看集群端口占用
kubectl get svc -A

kind 本地集群里，用 NodePort 访问时记得用 kubectl get svc 输出的 PORT(S) 列里的端口号，而不是 80。

清理本地环境 

# 删除所有 kind 集群
kind delete cluster

# 查看还剩哪些集群
kind get clusters

# 删除命名空间及其所有资源
kubectl delete namespace demo
删除命名空间是异步的，资源不会立刻消失，可以加 --wait=false 立即返回，或者用 kubectl get ns 确认状态。
