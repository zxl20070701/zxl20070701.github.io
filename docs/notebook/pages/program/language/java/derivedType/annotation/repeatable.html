重复注解

为什么要容器注解

Java 最初的语法规定一个位置只能贴同一个注解一次，所以「重复」这件事只能靠一个容器装起来： @Repeatable 指向一个容器注解，容器里放一个数组元素。 

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@Repeatable(Tags.class)
@interface Tag { String value(); }

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Tags { Tag[] value(); }

使用与读取 

@Tag("a")
@Tag("b")
public void multi() { }

// 读取
Tag[] tags = Demo.class.getMethod("multi").getAnnotationsByType(Tag.class);
// 输出：[@Demo.Tag("a"), @Demo.Tag("b")]

要注意两点：一是读取必须用 getAnnotationsByType ， getAnnotation(Tag.class) 会返回 null，因为元素上实际存的是容器注解；二是 getAnnotations() 拿到的是容器实例 @Tags ，而不是两枚 @Tag 。

容器注解的约束

  • 容器的 @Target 必须覆盖被重复注解的 @Target ，否则编译报错。
  • 容器的 @Retention 不能比被重复注解的短，否则同样编译失败。
  • 容器必须有且只有一个名为 value 的元素，类型是被重复注解的数组。

实践里重复注解用得不多，典型场景是「同一个方法要挂多条同类规则」：多条权限、多组参数校验、多个数据源标记。这类需求如果只有一个值，不如让元素的类型直接是数组。
