元注解

贴在注解上的注解

元注解用来描述一个注解自身的性质：保留到哪一层、能贴在哪里、能否重复、是否传给子类。JDK 在 java.lang.annotation 包里提供了这几个：

  • @Retention：保留策略，SOURCE / CLASS / RUNTIME 三档，不写时默认 CLASS。
  • @Target：允许贴的位置，TYPE、METHOD、FIELD、PARAMETER、CONSTRUCTOR、ANNOTATION_TYPE 等，可传数组指定多个。
  • @Documented：让注解出现在 javadoc 里，纯文档意义。
  • @Inherited：只有类注解能用，子类未声明时从父类继承；对方法、字段无效。
  • @Repeatable：允许同一个位置写多次，需要配一个容器注解。

@Target 写窄了会怎样 

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@interface OnlyMethod { }

class Wrong {
    @OnlyMethod int x;        // 编译错误：批注接口不适用于此类型的声明
}

@Target 起的是编译期保护作用：贴错位置立刻报错，而不是等到运行时反射返回 null。对框架注解来说，这条保护很有价值——它把「用法错」和「配置错」分成了两类问题。

@Inherited 只对类生效

这是最容易误解的一条：注解不在继承体系里，普通方法是读不到父类方法上的注解的； @Inherited 只对类注解生效，并且只是让子类「看起来也有了这个注解」。 

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@Inherited
@interface Tagged { String value(); }

@Tagged("父类标签")
class Base { }

class Child extends Base { }

// Child.class.getAnnotation(Tagged.class) → @Tagged("父类标签")
// 去掉 @Inherited 后，同样的调用返回 null

实测就是这两行输出：带 @Inherited 时子类能读到父类的标签，去掉之后返回 null。所以想在子类上生效的类注解，务必记得加这个元注解。
