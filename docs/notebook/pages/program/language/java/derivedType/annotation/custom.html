自定义注解

用 @interface 声明

自定义注解用一个特殊的接口声明：关键字 @interface ，里面写的是元素，不是普通方法。 

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target({ ElementType.METHOD, ElementType.TYPE })
public @interface Audit {

    String value();                                  // 没有默认值，使用时必须赋值

    int level() default 1;                           // 有默认值，可以省略

    String[] tags() default {};                      // 数组的空值写成 {}
}

元素的规则

  • 元素无参、不能抛异常、不能有方法体，写法上像一个不带实现的方法。
  • 返回类型只允许基本类型、String、Class、枚举、其他注解，以及它们的数组；不能是 Object、List 或泛型。
  • 元素可以有默认值，默认值必须是常量表达式，写 default null 会直接编译失败，报「元素值必须为常量表达式」。
  • 没有默认值的元素，使用该注解时必须全部赋值；漏一个就是编译错误。
  • 注解类型本身也不能带类型参数，声明成泛型会报「批注接口 X 不能为泛型」。

使用时的两种写法 

@Audit("下单")
public void create() { }

@Audit(value = "支付", level = 3, tags = { "money", "core" })
public void pay() { }

只有一个名为 value 的元素要赋值时，可以省略元素名，直接写 @Audit("下单") ；一旦同时要赋多个元素，就得把名字写全，元素之间用逗号分隔。

单值注解的常见用法

绝大多数自定义注解只带一个 value，用来放一个标识或一段描述，例如 @Log("下单") 、 @Permission("order:create") 。真正需要多个元素时，通常意味着注解的职责已经不单一，可以拆成两个注解。
