拦截器与过滤器

HandlerInterceptor 三个回调 

public class LoginInterceptor implements HandlerInterceptor {

    // 目标方法执行之前：这里返回 false 就中断请求
    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response, Object handler) throws Exception {
        if (request.getSession().getAttribute("user") == null) {
            response.sendRedirect("/login");
            return false;
        }
        return true;
    }

    // 目标方法执行之后、渲染之前
    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response,
                           Object handler, ModelAndView modelAndView) { }

    // 整个请求结束后（含异常），适合清理资源
    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) { }
}

注册拦截器

XML 写法，可以配顺序和路径匹配。多个拦截器按声明顺序执行 preHandle，按相反顺序执行 afterCompletion。 

<mvc:interceptors>
    <mvc:interceptor>
        <mvc:mapping path="/api/**"/>
        <mvc:exclude-mapping path="/api/login"/>
        <bean class="io.github.zxl20070701.springmvc.interceptor.LoginInterceptor"/>
    </mvc:interceptor>
</mvc:interceptors>

注解写法：实现 WebMvcConfigurer 的 addInterceptors，Spring Boot 项目里也是同一个接口，只是不再写 XML。 

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor())
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/login");
    }
}

和 Filter 的区别

  • Filter 属于 Servlet 规范，在 DispatcherServlet 之前执行，拿不到「将要调用哪个方法」的信息，也能拦静态资源。
  • 拦截器 属于 Spring MVC，在 DispatcherServlet 内部执行，能拿到 handler（方法信息）、ModelAndView，还能向容器注入 Bean。
Filter → DispatcherServlet → Interceptor(preHandle) → Controller
                          ← Interceptor(postHandle) ←
                          ← Interceptor(afterCompletion) ←

记忆点：需要在 Spring 上下文里工作（注入 Service、读写容器里的 Bean）就用拦截器；完全不依赖 Spring、要处理编码或跨域这类底层问题就用 Filter。

典型用途与坑

  • 登录校验、权限判断：preHandle 里判断，不通过直接返回 false 并写响应。
  • 接口耗时统计：preHandle 记开始时间，afterCompletion 打印。
  • 坑一：preHandle 返回 false 时如果不写响应体，客户端会收到一个空 200，看起来像「接口没返回数据」。
  • 坑二：拦截器对静态资源也会生效，路径匹配写 /** 时记得排除 /static/**、/**/*.js 这类。
  • 坑三：拦截器里抛异常会走统一异常处理，但那时响应可能已经提交，日志里能看到 IllegalStateException: response already committed。
