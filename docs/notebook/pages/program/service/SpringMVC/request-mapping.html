映射与参数绑定

@RequestMapping 与其组合注解 

@RequestMapping("/users")            // 类上写前缀，方法上写剩余部分
public class UserController {

    @GetMapping("/{id}")             // = @RequestMapping(value="/{id}", method=GET)
    public User get(@PathVariable("id") Long id) { ... }

    @PostMapping("/")
    public User create(@RequestBody User user) { ... }
}

@GetMapping / @PostMapping / @PutMapping / @DeleteMapping 都是 @RequestMapping 的组合注解，唯一区别是内置了 method。团队里通常统一用组合注解，读代码时能直接看出方法语义。

@RequestMapping 的常用属性

  • value / path：路径，支持 {变量} 占位。
  • method：只接受哪些 HTTP 方法，不匹配返回 405。
  • params：要求请求里带某些参数，例如 params = "action=save"。
  • headers：要求某些请求头。
  • consumes / produces：限定请求体的 Content-Type 和响应的 Content-Type。

参数怎么进方法 

@GetMapping("/search")
public String search(
        @RequestParam(value = "keyword", required = false, defaultValue = "") String keyword,
        @RequestParam(value = "page", defaultValue = "1") int page,
        @RequestHeader(value = "token", required = false) String token) { ... }
  • @RequestParam：取查询串或表单字段。required 默认 true，取不到直接 400；给了 defaultValue 就不会因为缺参数报错。
  • @PathVariable：取路径占位符，和 /{id} 配对使用。
  • @RequestBody：取请求体，按消息转换器反序列化成对象，需要 JSON 依赖。
  • @ModelAttribute：把一组参数绑到对象属性上，表单提交常用。
  • @RequestHeader / @CookieValue：取请求头、Cookie。

简单类型（String、int、long 等）不加注解时，默认按参数名从请求里取值，规则等同于 @RequestParam。

为什么参数名必须写死

Spring 6.1 起不再从字节码里「猜」参数名，必须能真实读到方法参数名。如果只写 @RequestParam 又不带 value，且编译时没加 -parameters，运行时会直接 500： 

Name for argument of type [java.lang.String] not specified, and parameter name
information not available via reflection. Ensure that the compiler uses the '-parameters' flag.

两个办法，建议都用上：注解里显式写 value；同时在 pom 里让编译器保留参数名。Spring Boot 的 parent 已经帮你加了这条编译参数，所以 Boot 项目里从未遇到这个问题——这正是「用 Boot 久了会忘记底层约定」的典型例子。 

<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.13.0</version>
    <configuration>
        <compilerArgs>
            <arg>-parameters</arg>
        </compilerArgs>
    </configuration>
</plugin>

多个映射都能匹配时选谁

Spring 会按「更具体优先」排序，大致是：精确路径 > 带路径变量的模式 > 通配符。例如 /users/me 和 /users/{id} 同时存在时，请求 /users/me 打到前者。

路径变量尽量少用正则，也避免同时存在 {a}/x 与 y/{b} 这类互相交叠的映射——虽然能跑，但后续加接口时非常容易踩到「莫名其妙进了另一个方法」。
