Bean 的三种注册方式

注解扫描

最常用的方式。类上写 @Component（或它的语义化子注解 @Service / @Repository / @Controller），容器扫描到包下的这些类就注册成 Bean。 

@Service
public class HelloService { }

@Repository
public class UserRepository { }

扫描范围由 <context:component-scan base-package="..."/> 或 @ComponentScan 指定。注意它只扫指定包的子包，包写错就会出现「容器里没有这个 Bean」的典型报错 NoSuchBeanDefinitionException。

XML 里写 bean

适合两种情况：一是第三方类不能改代码加注解，二是想显式看到对象是怎么拼出来的。JDK 自带类型也能这样交给容器。 

<bean id="appName" class="java.lang.String">
    <constructor-arg value="SpringCore 最小示例"/>
</bean>

<!-- 引用另一个 Bean 作为构造参数 -->
<bean id="greetingTask" class="io.github.zxl20070701.springcore.task.GreetingTask">
    <constructor-arg ref="appName"/>
</bean>

Java 配置类 + @Bean

Spring 3.0 之后可以不写 XML，用配置类代替。@Bean 标注在方法上，方法返回值就是注册进容器的对象，方法名默认是 Bean 名。 

@Configuration
@ComponentScan("io.github.zxl20070701.springcore")
public class AppConfig {

    @Bean
    public String appName() {
        return "SpringCore 最小示例";
    }

    // 需要别的 Bean 时，直接作为方法参数，容器会注入
    @Bean
    public GreetingTask greetingTask(String appName) {
        return new GreetingTask(appName);
    }
}

启动时换一个实现类即可：new AnnotationConfigApplicationContext(AppConfig.class)。

怎么选

  • 自己写的类，优先注解扫描，省事。
  • 第三方类、需要精细控制构造过程，用 @Bean 或 XML。
  • 同一个 Bean 不要在两处重复注册，否则按名字覆盖，排查起来很费时间。

三种方式可以混用

一个容器里同时存在 component-scan、XML bean、@Bean 完全合法。Spring 把它们统一转换成 BeanDefinition 注册进容器，之后所有使用方只看到「容器里有这么个 Bean」，不关心它怎么来的。 

<!-- XML 里也可以引入 Java 配置类 -->
<bean class="io.github.zxl20070701.springcore.AppConfig"/>
