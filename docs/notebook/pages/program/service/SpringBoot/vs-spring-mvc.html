与 Spring Core、Spring MVC 的关系

一图说清 

Spring Framework
├── Spring Core        IOC 容器、Bean、依赖注入、AOP       ← 一切的地基
├── Spring MVC         DispatcherServlet + Web 处理组件     ← 依赖 Core
└── Spring Boot        starter 依赖 + 自动配置 + 内嵌容器    ← 把上面两者打包好

Spring Boot Web ≈ Spring Core + Spring MVC + 自动配置 + 内嵌 Tomcat + 版本管理

关键认知：Spring Boot 不是 Spring MVC 的替代品。你没有「从 Spring MVC 换成 Boot」，而是「用 Boot 来组织 Spring MVC」。控制器里写的 @RestController、@GetMapping、@RequestParam，全部来自 Spring MVC。

Boot 到底替你省了什么

  • web.xml 里的 DispatcherServlet：由 DispatcherServletAutoConfiguration 自动注册，映射到 /。
  • springmvc.xml 里的组件注册：由 WebMvcAutoConfiguration 完成，等于自动写好了 <mvc:annotation-driven/>。
  • 依赖与版本：spring-boot-starter-web 聚合 spring-webmvc + jackson + tomcat，版本由 parent 统一管。
  • Servlet 容器：内嵌 Tomcat，main 方法启动，不用装、不用部署 war。
  • 字符编码过滤器：HttpEncodingAutoConfiguration 注册 CharacterEncodingFilter。
  • 编译参数 -parameters：parent 里已配置，参数名能被反射读到，所以 @RequestParam 不写名字也不报错。
  • 消息转换器字符集：默认 UTF-8，所以返回中文不会变成问号。

后两条特别值得记住：它们不是「Boot 更聪明」，而是「原生项目里需要你自己补，Boot 替你补了」。一旦你写原生项目或迁移老项目，这些默认值就全部消失。

原生项目里必须自己做的三件事

同样的 Controller 代码，从 Boot 搬到纯 Spring MVC 后经常会 500 或乱码，原因就这三处：

  • 编译器加 -parameters，并在 @RequestParam / @PathVariable 里写死名字，否则报 Name for argument ... not specified。
  • 返回字符串的接口加 produces = "text/plain;charset=UTF-8"，否则 StringHttpMessageConverter 按 ISO-8859-1 写出中文问号。
  • 返回对象时要自己加 Jackson 依赖，否则没有 JSON 消息转换器可用。

什么时候该用哪个

  • 新项目：默认 Boot，省配置、生态齐、部署简单。
  • 学习：先 Core（容器怎么管对象）→ 再 MVC（请求怎么走）→ 最后 Boot（这些是怎么被自动化的）。反过来先学 Boot，容易只会写注解、不懂为什么。
  • 老项目：SSM（Spring + Spring MVC + MyBatis）还在大量存在，没有 web.xml 之外的配置能力时，仍然要手写这些。
  • 特殊部署：必须共享外置容器、或公司统一用 war 时，Boot 也能打成 war（继承 SpringBootServletInitializer）。

一句话总结

Spring Core 管对象，Spring MVC 管请求，Spring Boot 管「怎么把前两者快速装起来」。三个词不是并列的三套技术，而是层层包含的三层。
