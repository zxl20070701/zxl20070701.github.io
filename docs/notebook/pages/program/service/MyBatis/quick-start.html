从零跑起来

MyBatis 是什么

MyBatis 是一个「半自动」的持久层框架：SQL 由你写，它负责把参数塞进 SQL、把结果集塞进对象。和 Hibernate、JPA 那种全自动 ORM 比，它不做表结构到对象的推导，也不会替你生成 SQL，所以复杂查询、慢 SQL 调优都完全可控——这也是国内项目大量用它的原因。

核心只有三样东西：一个全局配置（数据源 + 设置）、一批 Mapper 接口、一批 Mapper XML（SQL 写在里面）。没有 Spring、没有容器，一个 main 方法就能跑。

依赖

只要两个包：mybatis 本身，和一个 JDBC 驱动。下面用 H2 内存库，好处是不用装数据库，进程退出数据就没了；换成 MySQL 时只改驱动坐标和 url，代码一行不动。

建表 

CREATE TABLE sys_user (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_name   VARCHAR(32)  NOT NULL,
    email       VARCHAR(128),
    status      TINYINT      DEFAULT 1,
    create_time TIMESTAMP    DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO sys_user (user_name, email, status) VALUES ('alice', 'alice@example.com', 1);
INSERT INTO sys_user (user_name, email, status) VALUES ('bob', 'bob@example.com', 1);
INSERT INTO sys_user (user_name, email, status) VALUES ('carol', 'carol@example.com', 0);

表名用 sys_user 而不是 user：user 在不少数据库里是保留字或内置表名（H2 里直接写 FROM user 会报语法错误），加个前缀能省掉一堆莫名其妙的报错。

实体与 Mapper 接口 

public class User {
    private Long id;
    private String userName;
    private String email;
    private Integer status;
    private LocalDateTime createTime;

    // 省略 getter / setter
}

public interface UserMapper {

    User selectById(Long id);

    List<User> selectAll();

    int insert(User user);

    int update(User user);

    int deleteById(Long id);
}

接口里没有实现类，也不需要实现类。MyBatis 用动态代理给这个接口生成实现：调用 selectById 时，它去配置里找「namespace 等于接口全限定名、id 等于方法名」的那条 SQL 执行。所以接口全限定名和 XML 的 namespace 必须一字不差，方法名和 SQL 的 id 也必须一致。

Mapper XML 

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="io.github.zxl20070701.mybatis.mapper.UserMapper">

    <select id="selectById" resultType="User">
        SELECT id, user_name, email, status, create_time
        FROM sys_user
        WHERE id = #{id}
    </select>

    <select id="selectAll" resultType="User">
        SELECT id, user_name, email, status, create_time
        FROM sys_user
        ORDER BY id
    </select>

    <insert id="insert" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO sys_user (user_name, email, status, create_time)
        VALUES (#{userName}, #{email}, #{status}, #{createTime})
    </insert>

    <update id="update">
        UPDATE sys_user
        SET user_name = #{userName}, email = #{email}, status = #{status}
        WHERE id = #{id}
    </update>

    <delete id="deleteById">
        DELETE FROM sys_user WHERE id = #{id}
    </delete>

</mapper>

三个细节值得记住：resultType="User" 里写的是别名而不是全类名，别名在全局配置的 typeAliases 里注册；useGeneratedKeys + keyProperty 让自增主键回填到对象的 id 字段，不写的话插入后拿不到 id；#{} 是占位符，会被编译成 JDBC 的 ?，不是字符串拼接。

全局配置 

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE configuration
        PUBLIC "-//mybatis.org//DTD Config 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-config.dtd">

<configuration>

    <!-- 把外部 properties 读进来，下面用 ${} 引用 -->
    <properties resource="db.properties"/>

    <settings>
        <!-- user_name -> userName，省掉大部分 resultMap -->
        <setting name="mapUnderscoreToCamelCase" value="true"/>
        <!-- 打印 SQL，开发期必开 -->
        <setting name="logImpl" value="STDOUT_LOGGING"/>
    </settings>

    <typeAliases>
        <typeAlias type="io.github.zxl20070701.mybatis.entity.User" alias="User"/>
    </typeAliases>

    <environments default="dev">
        <environment id="dev">
            <transactionManager type="JDBC"/>
            <dataSource type="POOLED">
                <property name="driver" value="${jdbc.driver}"/>
                <property name="url" value="${jdbc.url}"/>
                <property name="username" value="${jdbc.username}"/>
                <property name="password" value="${jdbc.password}"/>
            </dataSource>
        </environment>
    </environments>

    <mappers>
        <mapper resource="mapper/UserMapper.xml"/>
    </mappers>

</configuration>

jdbc.driver=org.h2.Driver
jdbc.url=jdbc:h2:mem:mybatis;MODE=MySQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1
jdbc.username=sa
jdbc.password=

dataSource 的 type 只有三种：UNPOOLED（每次新建连接，只适合调试）、POOLED（内置连接池，够用）、JNDI（从容器取）。POOLED 是 MyBatis 自带的简易池，生产上一般换成 Druid 或 HikariCP，接入 Spring 后就是把 dataSource 换掉而已。

跑起来 

public class Main {

    public static void main(String[] args) throws Exception {

        SqlSessionFactory factory;
        try (Reader reader = Resources.getResourceAsReader("mybatis-config.xml")) {
            factory = new SqlSessionFactoryBuilder().build(reader);
        }

        initSchema(factory);    // 只在示例里需要：建表 + 灌初始数据

        // openSession()   默认不自动提交，写操作要自己 commit()
        // openSession(true) 自动提交，示例里省事
        try (SqlSession session = factory.openSession(true)) {

            UserMapper userMapper = session.getMapper(UserMapper.class);

            System.out.println(userMapper.selectById(1L));

            User user = new User();
            user.setUserName("dave");
            user.setEmail("dave@example.com");
            user.setStatus(1);
            user.setCreateTime(LocalDateTime.now());
            userMapper.insert(user);
            System.out.println("回填的主键 = " + user.getId());

            System.out.println("删除行数 = " + userMapper.deleteById(user.getId()));
        }
    }
}

// 建表由外部工具负责，示例里用 ScriptRunner 跑一次 schema.sql
private static void initSchema(SqlSessionFactory factory) throws Exception {
    try (SqlSession session = factory.openSession();
         Reader schema = Resources.getResourceAsReader("schema.sql")) {
        ScriptRunner runner = new ScriptRunner(session.getConnection());
        runner.setLogWriter(null);
        runner.runScript(schema);
        session.commit();
    }
}

建表和初始数据不在 MyBatis 的职责里，示例用 ScriptRunner 执行 schema.sql 完成初始化（这个类本身来自 mybatis 包，跑测试脚本很方便）。真实项目里建表交给 Flyway、Liquibase 或 DBA。

三个对象，三种生命周期

  • SqlSessionFactoryBuilder：只负责读配置、造工厂，造完就可以丢。方法级局部变量。
  • SqlSessionFactory：重量级，但线程安全，一个应用只留一个实例（静态字段或交给 Spring 管），反复 new 会不停重解析 XML、重建连接池。
  • SqlSession：轻量但不线程安全，代表一次数据库会话，用完必须 close 把连接还给池。一次请求一个，绝对不能做成单例或成员变量共享。

把 SqlSession 塞进 Controller 的字段里，是新手最典型的错误：并发时两个线程共用一个连接，轻则事务串味，重则连接被提前关闭，报 Connection is closed。

两个必踩的坑

  • Invalid bound statement (not found)：namespace、SQL 的 id、方法名三者有任何一个对不上，或者 XML 没在 <mappers> 里注册（mapper 放在 resources 下没被打进 classpath 也会这样）。
  • 插入成功但查不到：openSession() 不带 true 时写操作不会提交，方法返回后连接一关，数据就回滚了。要么 commit，要么开自动提交。
