Compose 与 View 混合使用

存量项目迁移时，两套体系往往需要长期共存。Compose 官方提供了双向互操作： ComposeView 把 Compose 塞进 XML， AndroidView 把 View 塞进 Compose。

方式一：ComposeView 嵌入 XML 布局（View → Compose） 

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical">

    <!-- 传统 View -->
    <TextView
        android:id="@+id/tv_title"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="旧页面标题" />

    <!-- Compose 容器 -->
    <androidx.compose.ui.platform.ComposeView
        android:id="@+id/compose_view"
        android:layout_width="match_parent"
        android:layout_height="wrap_content" />
</LinearLayout>

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        findViewById<TextView>(R.id.tv_title).text = "来自 View 的标题"

        findViewById<ComposeView>(R.id.compose_view).apply {
            // 跟随宿主生命周期销毁组合，避免内存泄漏
            setViewCompositionStrategy(
                ViewCompositionStrategy.DisposeOnViewTreeLifecycleDestroyed
            )
            setContent {
                MyAppTheme {
                    Column(modifier = Modifier.padding(16.dp)) {
                        Text("这段文字由 Compose 渲染")
                        Button(onClick = { /* ... */ }) {
                            Text("Compose 按钮")
                        }
                    }
                }
            }
        }
    }
}
ComposeView 默认的释放策略是 DisposeOnDetachedFromWindow， 放在 RecyclerView / ViewPager 中会因视图回收丢失状态， 务必显式改为 DisposeOnViewTreeLifecycleDestroyed。

方式二：Activity 整体使用 Compose

AppCompatActivity 同样支持 setContent，迁移期无需改基类： 

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()

        // 整个页面由 Compose 绘制
        setContent {
            MyAppTheme {
                HomeScreen()
            }
        }
    }
}

方式三：AndroidView 嵌入传统 View（Compose → View） 

@Composable
fun MapScreen() {
    val context = LocalContext.current
    var zoom by remember { mutableFloatStateOf(10f) }
    // remember 保证重组时不会重复创建 View
    val mapView = remember { MapView(context) }

    AndroidView(
        factory = { mapView },
        modifier = Modifier.fillMaxSize(),
        update = { view ->
            // 每次重组时回调，可在这里同步最新状态
            view.setZoom(zoom)
        }
    )

    // 组合退出时释放资源
    DisposableEffect(Unit) {
        onDispose { mapView.onDestroy() }
    }
}

嵌入 WebView 等需要跟随生命周期的 View 时， 同样在 DisposableEffect 中做清理。

状态互通：共享 ViewModel

View 与 Compose 之间不要直接互相持有控件，统一通过 ViewModel + StateFlow 交换数据： 

class SharedViewModel : ViewModel() {
    private val _count = MutableStateFlow(0)
    val count: StateFlow<Int> = _count.asStateFlow()

    fun increase() {
        _count.update { it + 1 }
    }
}

// View 侧：手动收集并更新控件
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        sharedViewModel.count.collect { value ->
            binding.tvCount.text = "计数：$value"
        }
    }
}

// Compose 侧：自动感知生命周期
@Composable
fun CounterText(viewModel: SharedViewModel) {
    val count by viewModel.count.collectAsStateWithLifecycle()
    Text("计数：$count", modifier = Modifier.clickable { viewModel.increase() })
}

混合使用的注意事项

  • 主题独立：XML 的 AppCompat 主题不会传递给 Compose， Compose 内容必须包一层 MaterialTheme（或自定义 Theme）。
  • 导航不要混用：同一页面栈内不要同时使用 Navigation Compose 和 Fragment Navigation，二者回退栈互不相通。
  • 尺寸单位：View 侧用 px/dp 换算，Compose 用 dp/sp， 跨边界传值统一使用 dp 值。
  • 减少嵌套层级：先把整块区域迁移为 Compose， 再逐步替换外围 View，避免 View ↔ Compose 反复嵌套。
新项目建议直接使用 ComponentActivity + Compose； 旧项目可保留 AppCompatActivity， 按页或按模块用 ComposeView 逐步替换，无需一次性重写。
