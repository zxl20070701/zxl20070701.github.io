安全的进程通信

Electron 的主进程和渲染进程通过 IPC 通信。推荐在 preload 中使用 contextBridge 暴露单一、明确的方法；不要向渲染页面暴露完整的 ipcRenderer 或 Node.js require。

渲染进程调用主进程并获取结果

主进程使用 ipcMain.handle 注册请求处理器，Preload 使用 ipcRenderer.invoke 转发请求。渲染层只调用通过 contextBridge 暴露的函数。

主进程（main.js）

const { app, ipcMain } = require("electron");

ipcMain.handle("app:get-version", () => {
    return app.getVersion();
});

Preload（preload.js）

const { contextBridge, ipcRenderer } = require("electron");

contextBridge.exposeInMainWorld("desktop", {
    getVersion: () => ipcRenderer.invoke("app:get-version")
});

渲染进程（renderer.js）

async function showVersion() {
    const version = await window.desktop.getVersion();
    console.log("应用版本：", version);
}

showVersion();

如果项目没有启用支持顶层 await 的模块配置，可以把调用放进 async 函数中。IPC 参数和返回值应使用可结构化克隆的数据。

主进程主动通知渲染进程

主进程可以通过窗口的 webContents.send 发送通知。Preload 应过滤 IPC 事件对象，只把需要的数据传给页面，并返回取消监听函数。

Preload（preload.js）

如需同时支持请求和通知，请把两个方法合并到同一个 desktop bridge 中： 

const { contextBridge, ipcRenderer } = require("electron");

contextBridge.exposeInMainWorld("desktop", {
    getVersion: () => ipcRenderer.invoke("app:get-version"),
    onStatusChanged: (callback) => {
        const listener = (_event, value) => callback(value);
        ipcRenderer.on("app:status-changed", listener);

        return () => {
            ipcRenderer.removeListener("app:status-changed", listener);
        };
    }
});

主进程（main.js）

const { BrowserWindow } = require("electron");

// 确认对应页面已经注册监听后，再发送通知。
for (const window of BrowserWindow.getAllWindows()) {
    window.webContents.send("app:status-changed", { ready: true });
}

渲染进程（renderer.js）

const unsubscribe = window.desktop.onStatusChanged((status) => {
    console.log("状态更新：", status);
});

// 页面不再需要监听时调用
unsubscribe();

不要使用同步 IPC

sendSync 会阻塞渲染进程，导致界面卡顿；新代码应优先使用 invoke/handle。若只需发送无需响应的通知，可以使用 send/on，并在页面卸载时清理监听。
