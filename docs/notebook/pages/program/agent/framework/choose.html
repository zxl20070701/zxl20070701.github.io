Agent 框架选型

Agent 框架的作用不是替你“变聪明”，而是帮你把模型、工具、状态、工作流、记忆和观测组织起来。选框架时要先看任务形态，再看语言生态，最后看团队能否长期维护。

常见框架定位

框架 特点 适合场景
LangChain 生态完整，模型、工具、Agent 接入丰富 快速搭建工具型 Agent、接入多模型和多工具
LangGraph 用图和状态机控制执行流程 需要分支、循环、可恢复状态的复杂任务
Mastra TypeScript 优先，Agent、Workflow、Memory、Tool 组合完整 Node.js 服务端、业务流程自动化、产品化 Agent
DeepAgents 基于 LangChain / LangGraph 的高层封装 研究任务、文件任务、多步骤深度执行
Pi Agent 更偏 Agent 产品和运行时内核拆解 学习 coding agent 架构、CLI Agent 产品形态

选型问题清单

  • 你的项目主要语言是 Python 还是 TypeScript？
  • 任务是自由探索，还是固定流程？
  • 是否需要长期状态、暂停恢复和人工审批？
  • 是否需要接大量第三方工具或 MCP Server？
  • 是否需要线上 trace、评估、重放测试和成本控制？

简单建议

  • 想快速理解 Agent 工具调用：先学 LangChain。
  • 想做可控流程：重点学 LangGraph。
  • 项目是 TypeScript 后端：优先看 Mastra。
  • 想研究 coding agent 或深度任务：看 DeepAgents 和 Pi Agent。
  • 生产系统不要只选“最火”的框架，要看可观测、状态持久化和权限控制。

组合使用

很多框架不是互斥的。LangChain 提供模型和工具抽象，LangGraph 负责图编排，DeepAgents 在其上封装深度任务能力。实际项目中可以先用高层 API 起步，遇到流程控制问题时再下沉到图或工作流。
