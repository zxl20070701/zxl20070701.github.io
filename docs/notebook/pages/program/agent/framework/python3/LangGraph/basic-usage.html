基本使用

LangGraph 是一个基于图（Graph）的 Agent 编排框架。它把一次任务的执行过程拆成一个个节点（Node），用边（Edge）把节点连成确定的路径，并在节点之间共享一份状态（State）。相比让模型自由发挥，图的方式流程可控，适合"步骤确定、需要精确编排"的场景。

安装

安装 LangGraph 和 OpenAI 协议的模型接入包： 

    pip3 install langgraph langchain-openai
本文的示例使用本地 Ollama 服务提供的模型，需要提前启动 Ollama 并拉取好模型（默认使用 qwen3.5）。

搭建第一个图

搭建一张图需要三步：定义状态、定义节点、用边把节点连起来。下面搭建一个最简单的图——只有一个"调用模型"的节点： 

#!/usr/bin/python3

from typing import TypedDict, List
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph
from langchain_core.messages import BaseMessage, HumanMessage


# 定义状态
class GraphState(TypedDict):
    messages: List[BaseMessage]


# 初始化 LLM
llm = ChatOpenAI(
    model="qwen3.5", api_key="ollama", base_url="http://localhost:11434/v1"
)


# 定义节点函数
def call_model(state: GraphState) -> GraphState:
    messages = state["messages"]
    response = llm.invoke(messages)
    return {"messages": messages + [response]}


# 创建图
workflow = StateGraph(GraphState)

# 添加节点
workflow.add_node("model", call_model)

# 添加边
workflow.add_edge("__start__", "model")
workflow.add_edge("model", "__end__")

# 编译图
app = workflow.compile()

# 运行图
result = app.invoke(
    {"messages": [HumanMessage(content="你是谁?")]}
)

print(result["messages"][-1].content)

逐段解读

状态（State）：用 TypedDict 定义整张图共享的数据结构，这里只有一个消息列表 messages。每个节点都从状态里读数据、往状态里写数据。

节点（Node）：一个普通的 Python 函数，入参是当前状态，返回值是要合并进状态的增量数据。call_model 做的事情就是把当前消息列表交给模型，再把模型的回复追加到列表里。

边（Edge）：通过 add_edge 声明节点的执行顺序。__start__ 和 __end__ 是两个特殊的虚拟节点，分别表示图的入口和出口。

图定义好之后必须调用 compile() 编译才能运行；编译后的应用通过 invoke 传入初始状态启动整张图。

这个例子只有一个节点，和直接调用模型差别不大；LangGraph 真正的威力在于多个节点组合——比如"模型节点 → 工具节点 → 模型节点"的循环，或者根据状态走不同分支的条件边，都可以用同样的方式搭建。
