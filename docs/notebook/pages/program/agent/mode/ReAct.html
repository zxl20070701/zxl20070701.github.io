ReAct 模式：让大模型边推理边行动

ReAct（Reeasoning + Acting）是 2022 年由普林斯顿与 Google Brain 团队提出的 Agent 范式。它的核心想法特别朴素：别让模型在脑子里空想，让它一边写推理过程，一边调用工具获取真实信息，再基于新信息继续推理。

今天几乎所有主流 Agent 框架（LangChain、LangGraph、OpenAI Agents、Cline、Cursor 等）底层的循环思想，都能追溯到这篇论文。

项目 信息

一句话理解 

思考（Thought） → 行动（Action） → 观察（Observation） → 思考 → 行动 → 观察 → ... → 最终答案

思考是把推理过程写出来，行动是调用外部工具，观察是工具返回的真实结果。三者交替出现，直到模型给出最终答案。

为什么需要 ReAct？

论文发表之前，「让模型推理」和「让模型行动」是两个被分开研究的方向，而它们各有致命短板。

只推理（CoT）的困境

Chain-of-Thought 通过让模型"一步步想"显著提升了推理能力，但整个过程是一个静态黑盒：模型完全依赖参数里的内部知识，一旦某个事实记错了，后续每一步都会在错误的基础上继续推理，最终变成彻底跑偏。

论文把它称为幻觉（hallucination）与错误传播（error propagation）。想象让模型凭记忆回答"某杂志创刊于哪一年"，它可能编出一个看起来非常合理的年份，而且越往后推理越自信。

只行动（Act）的困境

反过来，如果只让模型输出动作（类似 WebGPT 的做法），模型虽然能联网，但不会规划。论文里 Act-only 的 Agent 会一边翻页一边重复同样的话，最后根本走不到"给出答案"那一步，因为它缺少把长链条串起来的推理能力。

ReAct 的解法

ReAct 把两者缝在一起，形成一个闭环：reason to act（用推理指导该做什么）和 act to reason（用行动获取的信息支撑推理）。

维度 CoT（只推理） Act（只行动） ReAct（推理 + 行动）
信息来源 模型内部知识 外部环境 内部知识 + 外部环境
能否纠正自己 不能 部分能 能
主要失败模式 幻觉事实、错误传播 目标分解失败、丢失状态 检索不到信息、陷入重复循环
可解释性 有推理链，但无法溯源 只有动作序列 可区分"内部知识"与"外部事实"

核心机制：扩展动作空间

从形式化角度看，论文把 Agent 的动作空间从 A 扩展为 A ∪ L，其中 L 是自然语言空间。

  • 普通动作 a ∈ A：会真正影响外部环境，比如搜索、点击、运行代码，因此会返回观察结果。
  • 语言动作 â ∈ L：也就是"思考"，不影响外部环境、没有观察反馈，但会更新上下文 c(t+1) = (c(t), â)，为后续推理和行动提供素材。

一句话：思考是"写给自己的备注"，行动是"和世界的对话"。两者都进入同一条上下文流，交替推进。

轨迹格式

论文用统一的三段式描述完整轨迹。以多跳问答为例（原文示例，已翻译）： 

问题：科罗拉多造山带东翼延伸区域的海拔范围是多少？

思考 1：我需要搜索科罗拉多造山带，找到东翼延伸到的区域，然后查该区域的海拔范围。
行动 1：Search[Colorado orogeny]
观察 1：科罗拉多造山带是科罗拉多及周边地区的一次造山运动。

思考 2：文中没有提到东翼，所以我需要查找"东翼"。
行动 2：Lookup[eastern sector]
观察 2：（第 1 条 / 共 1 条）东翼延伸至高平原，被称为中央平原造山带。

思考 3：东翼延伸至高平原，所以我需要搜索高平原并查找其海拔范围。
行动 3：Search[High Plains]
观察 3：高平原指两个不同的陆地区域之一。

思考 4：我应该改搜 High Plains (United States)。
行动 4：Search[High Plains (United States)]
观察 4：高平原是大平原的次区域。从东到西，高平原海拔从约 1,800 英尺上升到 7,000 英尺。

思考 5：高平原海拔从约 1,800 到 7,000 英尺，所以答案是 1,800 到 7,000 英尺。
行动 5：Finish[1,800 to 7,000 ft]
注意观察到的细节：思考 3 之后模型得到的只是模糊条目，于是它主动改写了检索词；思考 2 则体现了"这段没说要什么"的自我察觉。这些都是纯 CoT 模式里不会出现的动作。

两种思考节奏

论文强调：思考出现的密度应该由任务性质决定，而不是一刀切。

任务类型 思考节奏 原因
知识密集型推理（问答、事实核查） 密集思考（dense） 步骤少但每一步都依赖上一步的信息，需要细粒度拆解与校验
交互式决策（游戏、网页操作） 稀疏思考（sparse） 动作可能高达几十上百步，每步都思考既昂贵又啰嗦，只在关键节点思考即可

稀疏思考场景下，模型自己决定"此刻要不要说一句"，思考与行动变成异步交错。论文给出的 ALFWorld 提示词就是这样设计的。 

你是站在房间中央。环顾四周，你看到柜子
1-6、咖啡机 1、台面 1-3、抽屉 1-3、冰箱 1、垃圾桶 1、微波炉 1、
置物架 1-3、水槽 1、炉灶 1-4、烤面包机 1。
你的任务是：把一把干净的刀放到台面上。

> 思考：为了完成任务，我需要先找到并拿起一把刀，然后用水槽清洗，最后放到台面上。
OK.
> 思考：我需要先找一把刀。刀更可能出现在柜子（1-6）、抽屉（1-3）、台面（1-3）里，我可以逐个查找，先从柜子 1 开始。
OK.
> go to cabinet 1
你看到柜子 1 上有一个碗 1。
...
这里用 think: 开头表示"思考"，其余行是真正的环境动作。环境中无意义的位置（没有刀的台面）会被跳过，模型会结合常识"台灯一般在桌子、置物架或衣柜上"来缩小搜索范围——这正是稀疏思考里最有价值的部分。

论文的四大优点

  1. 直观易设计：提示词就是人类在动作上"把自己的想法写出来"，不需要复杂的格式设计、思维链模板或示例挑选技巧。
  2. 通用灵活：思考空间自由、动作格式可定制，同一套范式能套到问答、事实核查、文本游戏、网页导航等不同动作空间的任务上。
  3. 性能强健：只用 1~6 个上下文示例就能泛化到新任务实例，稳定优于"只推理"或"只行动"的基线；论文还验证了微调后的进一步提升。
  4. 人类对齐可控：推理轨迹可读可查，人类可以中途编辑模型的想法来纠正行为（详见后文"人在环路"）。

实验一：知识密集型推理

任务与动作空间

论文在两个数据集上验证：HotpotQA（需要跨多篇文档推理的多跳问答）和 FEVER（事实核查，标注为 SUPPORTS / REFUTES / NOT ENOUGH INFO）。两者都采用只给问题、不给背景资料的设置，模型必须自己决定去检索什么。

为了模拟人类操作维基百科，作者设计了一个极简的 API，只有三个动作：

  • search[实体]：返回该实体 wiki 页的前 5 句；若不存在则给出最相似的 5 个候选实体。
  • lookup[字符串]：返回当前页面中包含该字符串的下一句，相当于浏览器的 Ctrl+F。
  • finish[答案]：结束任务并给出答案。

这个动作空间比真正的检索器弱得多（只能靠精确名称取到片段），目的正是逼模型靠显式推理来驱动检索。

四种提示方法

论文通过"消融"同一批 ReAct 轨迹来构造基线，这组对比是全文最有说服力的部分：

方法 保留了什么 代表的能力
Standard 只留问题和答案 纯参数化知识
CoT 保留思考，去掉动作与观察 只推理
CoT-SC CoT + 采样 21 条轨迹取多数答案 只推理 + 自洽性投票
Act 保留动作与观察，去掉思考 只行动
ReAct 思考 + 动作 + 观察 推理与行动协同

结果

基于 PaLM-540B 的提示词实验结果：

提示方法 HotpotQA（EM） FEVER（Acc）
Standard 28.7 57.1
CoT 29.4 56.3
CoT-SC 33.4 60.4
Act 25.7 58.9
ReAct 27.4 60.9
CoT-SC → ReAct 34.2 64.6
ReAct → CoT-SC 35.1 62.0
监督学习 SoTA 67.5 89.5

可以读出三条结论：

  • ReAct 稳定优于 Act：说明"用推理指导行动"确实有价值，尤其是在综合最终答案时。
  • ReAct 与 CoT 互有胜负：HotpotQA 上 ReAct 略低于 CoT（27.4 vs 29.4），但 FEVER 上明显更高（60.9 vs 56.3）。原因是事实核查的 SUPPORTS/REFUTES 往往只差几个字，必须查到准确且最新的信息才行。
  • 混合策略最好：CoT-SC → ReAct 在 FEVER 上达到 64.6，ReAct → CoT-SC 在 HotpotQA 上达到 35.1；两者都稳定超过单独使用 CoT-SC，且用 3~5 个采样就达到了 CoT-SC 采样 21 次的效果。

实验二：交互式决策

论文还在两个需要长程交互、奖励稀疏的环境上测试：ALFWorld（文本版家居模拟，一个任务可能涉及 50+ 个位置、专家也要 50+ 步）和 WebShop（118 万真实商品的购物网站环境）。

ALFWorld 任务成功率（%）

方法 Pick Clean Heat Cool Look Pick 2 All
Act（6 次最佳） 88 42 74 67 72 41 45
ReAct（平均） 65 39 83 76 55 24 57
ReAct（6 次最佳） 92 58 96 86 78 41 71
ReAct-IM（6 次最佳） 62 68 87 57 39 33 53
BUTLER（模仿学习） 46 39 74 100 22 24 37

两个关键点：最差的一次 ReAct（48%）仍然打败了 Act 的最好一次（45%）和 BUTLER 的最好一次（37%）；而在 6 组受控对比中，ReAct 相对 Act 的相对提升在 33%~90% 之间，平均 62%。

也就是说，只用 1~2 个示例的提示词，就超过了用上千条人工轨迹训练的模仿学习和强化学习方法，成功率绝对提升 10%。

失败模式分析

论文随机抽取了 200 条轨迹（ReAct 和 CoT 各 50 条正确 + 50 条错误）做人工标注，结论非常有指导意义：

类型 定义 ReAct CoT
成功 · 真阳性 推理链与事实都正确 94% 86%
成功 · 假阳性 推理链或事实存在幻觉 6% 14%
失败 · 推理错误 推理链错误（含陷入重复循环） 47% 16%
失败 · 检索错误 搜索返回空或无用信息 23% -
失败 · 幻觉 推理链或事实被凭空编造 0% 56%
失败 · 标注歧义 预测正确但未精确匹配标注 29% 28%

三个洞察：

  • CoT 的头号杀手是幻觉，占其失败案例的 56%；ReAct 因为有外部知识兜底，幻觉占比直接为 0%——这正是"让模型接触真实世界"的价值。
  • ReAct 的代价是推理灵活性下降。因为每一步都被"思考 → 动作 → 观察"的结构约束住了，模型有时会机械地重复上一步的思考和动作，掉进循环里出不来。
  • 检索质量直接决定成败。23% 的失败是搜了个寂寞，模型拿到无用信息后很难自我修复和重新组织检索词。
换成现代 Agent 的语言：工具返回的信息质量，和 是否会陷入重复调用，是评估 ReAct 类系统最值得盯的两个指标。

进阶玩法

混合 ReAct 与 CoT-SC

既然"外部检索更可靠"和"内部推理更结构化"各有优势，论文让模型自己决定何时切换：

  • ReAct → CoT-SC：ReAct 在限定步数内没能给出答案时，退回 CoT-SC。HotpotQA 限 7 步、FEVER 限 5 步（因为更长的轨迹几乎不再提升正确率）。
  • CoT-SC → ReAct：当 21 条 CoT 采样中多数答案的出现次数不足一半时，说明模型内部知识对这个任务并不自信，转而使用 ReAct 去查证。

自举式微调

人工标注推理轨迹太贵，论文借鉴 STaR 的思路：先用 ReAct 生成 3000 条答案正确的轨迹，再用这些轨迹微调更小的模型（PaLM-8B / 62B）去解码完整的"思考 + 动作 + 观察"序列。

结果很有意思：用提示词时，小模型跑 ReAct 表现最差（因为它很难仅从几个示例里同时学会推理和行动），但微调之后 ReAct 反而成为四者中最强的方法——微调后的 PaLM-8B 超过了所有 PaLM-62B 的提示词结果。

作者的解释很到位：微调 Standard 或 CoT 本质上是在教模型背诵知识（还可能背进幻觉），而微调 ReAct 或 Act 教的是"如何去获取信息"这种可迁移的技能。

人在环路：编辑模型的想法

论文附录里做了一个很吸引人的实验：在 ALFWorld 中，ReAct 因为一句幻觉的想法而失败；人类只是删掉第 17 步的一句幻觉，并在第 23 步加了一句提示，整条轨迹就转危为安、任务成功。

对人类来说，介入成本从"手打几十个动作"降到了"改两句话"。这种能力是 Act 或早期强化学习方法给不了的——你没法通过改几个动作去改变模型的参数，也没法让模型自己长出新习惯。

ReAct 与 Inner Monologue 的区别

论文认为 ReAct 是第一个在交互式环境中用 LLM 实现"推理 + 行动"闭环的工作，而 Inner Monologue（IM）的"内心独白"只是环境反馈的复述，仅限于"当前看到了什么、目标还差什么"，缺少目标分解、常识推理等高层思考。

消融实验支持了这个论断：ReAct 总体成功率 71%，而 IM 风格的 ReAct-IM 只有 53%。IM 常常搞不清子目标是否完成、下一个子目标该是什么，也缺少"台灯一般在哪"这类常识判断。

局限性

  • 提示词范式有上限：动作空间大、任务复杂时需要更多示例，容易超出上下文长度限制。
  • 离领域 SOTA 仍有距离：HotpotQA 上 35.1 对监督学习的 67.5，差距明显，作者认为需要更多人工标注数据。
  • 成本与延迟：每一步思考都会多消耗一次模型调用，长任务里 token 消耗会迅速膨胀。
  • 循环与假死：贪心解码下容易重复上一步动作，作者猜测用 beam search 之类的更好解码策略会有帮助。
  • 安全风险：论文专门强调，把 LLM 接到真实环境（网页、文件系统、支付）上有危险，实验中被限制在 Wikipedia 和 WebShop 这类无副作用的环境里。

今天如何落地 ReAct

论文写于 2022 年，但它的思想已经内化进现代 Agent 工程。做一个对照翻译：

论文概念 现代工程对应
Thought 模型输出中的自然语言推理（也可用推理模型代替显式 CoT）
Action function calling / tool call
Observation 工具返回值（消息列表中 role 为 tool 的消息）
动作空间 A ∪ L 工具集 + 自由文本输出
finish[answer] 结构化最终答案，或专门的终止工具
密集 / 稀疏思考 每次工具调用前都推理，或只在关键节点推理
人类编辑思考 中断任务、修正历史消息后继续执行

一个最朴素的 ReAct 循环，大概就是这样： 

messages = [{"role": "user", "content": question}]

for _ in range(MAX_STEPS):
    # 1) 思考 + 行动：模型自己决定这一步说什么、调用什么工具
    response = llm.invoke(messages, tools=tool_schemas)

    # 2) 没有工具调用，说明模型认为已经想清楚了
    if not response.tool_calls:
        return response.content

    messages.append(response)

    # 3) 行动 → 观察：执行工具，把真实结果写回上下文
    for call in response.tool_calls:
        result = run_tool(call.name, call.args)
        messages.append({
            "role": "tool",
            "tool_call_id": call.id,
            "content": str(result),
        })

raise RuntimeError("超过最大步数仍未得到答案")
