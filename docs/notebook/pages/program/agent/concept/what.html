什么是 Agent？

Agent 通常指具备一定自主性的 AI 应用：它不只是回答一次问题，而是会围绕一个目标，自己判断下一步该做什么，必要时调用工具、读取资料、执行代码，并根据结果继续调整行动。

和普通 ChatBot 的区别

普通 ChatBot 更像“问一句答一句”的对话接口；Agent 更像“带着目标工作的执行系统”。它会把用户意图转成任务状态，再通过规划、工具调用、记忆和反馈循环逐步推进。

维度 ChatBot Agent
目标 生成回复 完成任务
执行方式 单轮或多轮对话 规划、行动、观察、迭代
外部能力 通常较少 可连接工具、文件、数据库、浏览器等
结果判断 主要看回答是否合理 还要看任务是否真实完成

Agent 的基本组成

大模型

大模型负责理解任务、生成计划、选择工具、解释结果，是 Agent 的推理核心。

工具

工具让 Agent 可以影响外部世界，比如搜索网页、读写文件、查询数据库、发送请求、运行代码等。

记忆

记忆用于保存对话历史、用户偏好、任务中间状态和长期知识，让 Agent 不必每次都从零开始。

编排层

编排层负责把“思考、调用工具、读取结果、继续决策”组织成一个可运行流程。很多 Agent 框架主要就是在解决编排问题。

一个最小运行循环

  1. 接收目标：理解用户真正想完成什么。
  2. 拆分任务：判断需要哪些步骤和信息。
  3. 选择动作：决定直接回答，还是调用工具。
  4. 观察结果：读取工具返回值、错误或环境变化。
  5. 更新状态：修正计划，继续下一步。
  6. 交付结果：给出最终答案、文件、代码或操作结果。

学习顺序建议

初学时可以按“概念 → 工具调用 → 记忆/RAG → 工作流 → 多 Agent → 评估与安全”的顺序学习。不要一开始就陷入框架 API，先理解 Agent 为什么需要这些部件，再去看 LangChain、LangGraph、Mastra 等框架会顺很多。

Agent 能力成熟度

阶段 能力 学习重点
问答助手 根据上下文回答问题 提示词、上下文组织
工具助手 能调用外部工具查询或执行 工具 Schema、权限、错误处理
任务 Agent 能规划多步任务并持续推进 状态管理、计划、重试、验收
工作流 Agent 能嵌入稳定业务流程 状态机、审批、观测、回放测试
多 Agent 系统 多个角色协作完成复杂任务 任务拆分、结果整合、成本控制

做 Agent 前先问的几个问题

  • 这个任务是否真的需要自主多步执行？
  • 模型需要哪些外部数据和工具？
  • 哪些动作可以自动执行，哪些必须人工确认？
  • 任务完成的验收标准是什么？
  • 失败后能否恢复，是否会产生重复副作用？
  • 如何记录过程，方便后续调试和评估？

学习路线

  1. 先手写一个最小工具调用 Demo，理解模型如何选择工具。
  2. 再加入状态保存，让任务可以多轮推进。
  3. 然后接入 RAG，让 Agent 能基于自己的资料库回答。
  4. 继续加入工作流，把高风险节点交给程序和人工控制。
  5. 最后补评估与观测，形成可迭代的工程闭环。
