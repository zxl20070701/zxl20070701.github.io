记忆与 RAG

记忆和 RAG 都是在解决同一个问题：模型上下文窗口有限，不能把所有信息一次性塞进去。区别在于，记忆更偏“保存和延续状态”，RAG 更偏“从外部知识库检索相关资料”。

记忆是什么？

记忆是 Agent 在任务过程中保存下来的信息，例如用户偏好、历史决策、任务进度、失败原因、已验证结论等。好的记忆不是简单保存全部聊天记录，而是保存之后真正会用到的结构化信息。

短期记忆

短期记忆通常存在于当前会话上下文中，用于维持多轮对话和任务状态，例如当前计划、已经读过的文件、刚刚执行过的命令结果。

长期记忆

长期记忆会跨会话保存，例如用户长期偏好、项目约定、常用账号信息、历史问题解决方案等。长期记忆需要更严格的隐私和更新策略。

RAG 是什么？

RAG（Retrieval-Augmented Generation）可以理解为“先检索，再生成”。系统先从文档、数据库、网页或向量库中找出和问题相关的片段，再把这些片段作为上下文交给模型回答。

RAG 基本流程

  1. 文档切分：把长文档切成适合检索的小块。
  2. 向量化：用 embedding 模型把文本转成向量。
  3. 建立索引：把向量和原文片段存入向量数据库。
  4. 查询检索：把用户问题向量化，找出相似片段。
  5. 重排过滤：去掉不相关内容，保留高质量上下文。
  6. 生成回答：模型基于检索结果生成答案。

记忆和 RAG 的区别

能力 记忆 RAG
核心目标 延续状态和偏好 查找外部知识
数据来源 交互过程、用户设置、任务记录 文档库、网页、数据库、知识库
更新频率 随任务动态变化 随知识库更新变化
风险 记错、过期、隐私泄露 检索不准、片段缺上下文、引用错误

常见问题

检索到了但回答不准

可能是切分粒度太碎、召回片段缺少上下文、排序质量不够，或者提示词没有要求模型只依据检索资料回答。

记忆越来越乱

说明缺少记忆写入规则。不是所有信息都应该写入长期记忆，只有稳定、可复用、经过确认的信息才值得保存。

实践建议

  • 先做一个简单可观测的检索链路，再优化向量库和重排。
  • 为长期记忆设置来源、时间和可信度，方便以后更新。
  • 回答重要问题时保留引用来源，便于用户检查。
  • 定期清理过期记忆，避免旧信息影响新任务。

什么时候用记忆，什么时候用 RAG？

如果信息来自用户长期偏好或任务过程，比如“我喜欢简洁回答”“这个项目使用 Vue”，更适合放进记忆。如果信息来自大量外部资料，比如产品手册、论文、接口文档，更适合放进 RAG。

记忆写入规则

  • 稳定信息才写入，例如用户偏好、长期项目约定。
  • 临时状态不要写入长期记忆，例如“刚刚打开了某个文件”。
  • 敏感信息默认不写入，例如密码、token、身份证号。
  • 矛盾信息需要确认后再覆盖旧记忆。
  • 每条记忆最好带来源和更新时间。

RAG 和 Agent 的结合

RAG 可以作为 Agent 的一个工具存在。Agent 在需要知识时调用检索工具，拿到资料后再决定是否继续查、是否调用业务工具、是否输出结论。 

用户问题
    ↓
Agent 判断需要资料
    ↓
调用 search_knowledge_base
    ↓
阅读检索结果
    ↓
资料不足则继续检索，资料足够则生成答案
