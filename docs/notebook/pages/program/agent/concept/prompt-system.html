提示词与系统指令

在 Agent 中，提示词不只是“问模型一句话”，而是用来定义角色、目标、约束、工具使用方式和输出格式的一组运行规则。提示词质量会直接影响 Agent 的稳定性。

常见指令层级

系统指令

系统指令定义 Agent 的最高优先级行为，例如身份、边界、安全规则、工具使用原则、回答风格等。

开发者指令

开发者指令通常描述应用级策略，例如业务流程、框架约定、代码风格、错误处理方式。

用户指令

用户指令表达当前任务目标，例如“帮我修复这个 bug”“总结这份文档”“生成一份周报”。

工具结果

工具结果是 Agent 行动后的观察信息，模型需要根据它判断下一步，而不是只依赖自己的猜测。

好提示词的特点

  • 目标明确：说明要完成什么，而不是只描述一个模糊方向。
  • 边界清楚：说明不能做什么、何时需要确认。
  • 输出稳定：规定必要的格式、字段或验收标准。
  • 可执行：给出行动规则，而不是空泛的价值判断。
  • 可迭代：能根据错误、反馈和新信息更新策略。

Agent 提示词模板 

你是一个用于完成【任务类型】的 Agent。

目标：
- 明确完成用户请求，并交付可验证结果。

工作方式：
- 先理解目标和约束。
- 必要时调用工具获取事实或执行操作。
- 每次工具调用后根据结果调整下一步。
- 遇到高风险或信息不足的情况，先请求用户确认。

输出要求：
- 给出最终结果。
- 简要说明关键依据。
- 如果未完成，说明阻塞原因和下一步建议。

常见问题

指令太泛

比如“你要认真负责”这类描述很难落实。更好的写法是定义具体行为：执行前检查输入、失败时重试一次、输出时列出验证结果。

工具边界不清

如果没有说明什么时候该用工具，模型可能凭记忆回答实时问题，也可能对简单问题过度调用工具。

输出格式不稳定

当结果要被程序继续处理时，应使用 JSON Schema、表格字段或固定段落结构，减少后续解析成本。

小结

提示词像 Agent 的操作手册：它不负责代替模型推理，但会给推理设定方向、边界和验收标准。越是复杂的 Agent，越需要把提示词当作工程资产维护。
