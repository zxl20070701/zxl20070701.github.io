工作流型 Agent

并不是所有 Agent 都要完全自主。很多生产系统更适合做成工作流型 Agent：流程由程序控制，模型只负责理解、分类、生成、选择局部动作。

自主 Agent 与工作流 Agent

类型 特点 适合场景
自主 Agent 模型自由决定步骤和工具 探索性研究、开放任务、代码助手
工作流 Agent 流程固定，模型在节点内发挥作用 客服、审批、报表、运营自动化

常见节点

  • 分类节点：判断任务类型、优先级、风险等级。
  • 抽取节点：从文本中提取结构化字段。
  • 检索节点：查询知识库、数据库或外部 API。
  • 决策节点：根据规则和模型判断下一步。
  • 执行节点：调用工具执行动作。
  • 审核节点：人工确认或自动校验。
  • 通知节点：把结果发送给用户或下游系统。

什么时候选择工作流？

  • 业务流程稳定，有明确步骤。
  • 需要审计、审批、权限和合规。
  • 错误成本较高，不能完全依赖模型自由发挥。
  • 需要和多个内部系统稳定集成。

模型放在哪里？

工作流里可以把模型放在局部节点中，而不是让模型控制全局。例如让模型负责“理解用户意图”和“生成回复文案”，但由程序决定是否可以退款、是否需要审批。

实践建议

  • 先画状态图，再写 prompt。
  • 把不可违反的业务规则写成代码，不要只写进提示词。
  • 每个节点都要有输入、输出和失败处理。
  • 对长流程保存状态，支持中断后继续。
  • 关键节点记录 trace，方便复盘。
