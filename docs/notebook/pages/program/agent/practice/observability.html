Agent 调试与可观测性

Agent 出错时，表面现象经常只是“回答不对”。要真正定位问题，需要看到它读了什么上下文、做了什么计划、调用了什么工具、工具返回了什么。

需要记录什么？

  • 用户请求：原始输入和任务 id。
  • 上下文：传给模型的关键资料摘要。
  • 模型调用：模型名称、参数、token、耗时。
  • 工具调用：工具名、参数、返回值、错误。
  • 状态变化：任务从哪个状态进入哪个状态。
  • 最终结果：输出内容和验收结果。

常见故障定位

现象 优先检查
回答编造 检索结果、系统指令、引用约束
工具选错 工具描述、工具数量、命名是否相似
参数错误 Schema、默认值、枚举、错误提示
反复重试 终止条件、错误分类、重试次数
成本过高 上下文长度、模型路由、重复检索

调试方法

固定输入回放

保存一批真实任务输入，修改 prompt、工具或模型后反复运行，对比成功率和调用轨迹。

分段验证

不要一次调试整个 Agent。先验证检索，再验证工具参数，再验证最终生成，每一段都有独立判断标准。

降低随机性

排查问题时可以降低 temperature，让结果更稳定。等链路稳定后，再根据场景调整创造性。

线上指标

  • 任务成功率
  • 平均响应时间
  • 平均工具调用次数
  • 人工介入比例
  • 失败原因分布
  • 单任务平均成本
