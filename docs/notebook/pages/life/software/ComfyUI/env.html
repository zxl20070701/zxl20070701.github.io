环境搭建

本文记录在 macOS（Apple M4 芯片）上从源码搭建 ComfyUI 的完整流程：用 Homebrew 的 Python 3.11 建独立虚拟环境，安装 PyTorch（走 MPS 后端，不需要 CUDA），再安装 ComfyUI 本体和插件管理器，最后启动 Web 界面。

环境准备

搭建前需要确认几件事，尤其是 Python 版本。ComfyUI 依赖的 PyTorch 目前只发布到 Python 3.13 的轮子，Python 3.14 是装不上的，会直接卡在 pip 解析依赖这一步。 

# 确认 python3 的版本（需要 3.11 / 3.12 / 3.13）
python3 --version

# 确认 git 和 Xcode 命令行工具
git --version
xcode-select -p

本文所用的机器环境如下，可作对照： 

系统：macOS 26.5.1（Apple M4，arm64）
Python：3.11.18（Homebrew python@3.11）
磁盘：剩余约 66 GB
如果 python3 指向的是 python.org 安装的 3.14，在 ~/.zshrc 里把 brew 的 python@3.11 放到 PATH 最前面即可，加一行 export PATH="/opt/homebrew/opt/python@3.11/libexec/bin:$PATH"，重开终端后生效。不要用系统自带的 Python 直接 pip install，macOS 有保护会报权限错误，一律走下面的虚拟环境。

拉取源码

选一个空间充足、不在 iCloud 同步目录下的位置存放代码。iCloud 目录会被同步进程反复扫描，装完依赖后启动会很慢。 

cd ~/Desktop
git clone https://github.com/comfyanonymous/ComfyUI.git
cd ComfyUI

创建虚拟环境

所有依赖都装在项目自己的 venv 里，不污染全局 Python 环境。 

python3 -m venv venv
source venv/bin/activate

激活成功后，终端提示符前面会出现 (venv) 前缀，此时 python3 指向的就是这个虚拟环境里的解释器。 

python3 -V
# 输出：Python 3.11.18
每开一个新的终端窗口，都要先 cd ~/Desktop/ComfyUI 再 source venv/bin/activate，否则会用到系统的 Python，导入模块时报 No module named 'torch'。

安装 PyTorch

Apple Silicon 上使用 PyTorch 官方的 macOS 轮子即可，它内置了 MPS（Metal Performance Shaders）后端，不用装 CUDA 版本。 

pip install --upgrade pip
pip install torch torchvision torchaudio

安装完成后验证 MPS 是否可用： 

python -c "import torch; print(torch.__version__, torch.backends.mps.is_available())"
# 输出：2.15.0 True

输出 True 表示 GPU 加速链路已经打通。

安装 ComfyUI 依赖 

pip install -r requirements.txt

这一步会装上前端包、工作流模板、各类图像处理库，国内网络较慢时可以先把 pip 源换成镜像再装： 

pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

安装 ComfyUI-Manager

ComfyUI-Manager 是节点和插件管理器，装上之后可以在界面里搜索、安装、更新自定义节点，不用再一个个手动 clone。 

cd custom_nodes
git clone https://github.com/ltdrdata/ComfyUI-Manager.git
cd ..

启动与验证 

python main.py

看到类似下面的输出就表示启动成功，浏览器打开 http://127.0.0.1:8188 即可进入界面： 

Starting server

To see the GUI go to: http://127.0.0.1:8188

首次生成图片会明显偏慢，因为 MPS 需要先编译内核，第二次之后就恢复正常速度。另外 M 芯片是统一内存架构，跑图时显存是从系统内存里切的，同时开太多应用容易把机器拖卡。

常用的启动参数： 

# 端口被占用时换一个
python main.py --port 8189

# 允许局域网内其它设备访问
python main.py --listen 0.0.0.0

# 低内存模式（内存紧张时使用）
python main.py --lowvram

模型目录

下载的模型按类型放进对应目录，界面里的节点才能在下拉列表中看到它。主要几个目录如下： 

ComfyUI/models/
├── checkpoints/          # 完整大模型（SD1.5 / SDXL / Flux）
├── diffusion_models/     # 单独发布的扩散模型（Flux 拆分版）
├── text_encoders/        # 文本编码器（Flux 用的 clip_l、t5xxl）
├── vae/                  # VAE 模型
├── loras/                # LoRA 微调模型
├── controlnet/           # ControlNet 控制模型
├── upscale_models/       # 放大模型（ESRGAN 等）
├── embeddings/           # 文本嵌入
└── clip_vision/          # 视觉编码器

在 M4 上不建议一上来就上最大的模型，先用 SD1.5 或 SDXL 的 fp16 权重（约 2~7 GB）把流程跑通，再考虑 Flux 的 fp8 或 GGUF 量化版本。

常见问题

一、pip install torch 时提示找不到匹配的发行版。 说明当前 Python 版本过新（如 3.14），PyTorch 还没有对应的轮子。换 3.11 或 3.12 重建虚拟环境即可。

二、启动时提示 No module named 'torch' 或 No module named 'comfy'。 终端没有激活虚拟环境。执行 source venv/bin/activate 后再启动。

三、浏览器打不开 8188 端口。 先看终端里是否已经打印出 To see the GUI go to 这一行；如果没有，说明启动失败，往上翻日志找第一个报错。如果端口被其它进程占用，用 python main.py --port 8189 换端口。

四、生成图片时报 MPS 相关错误或内存不足。 降低分辨率与批量大小，或改用量化模型；也可以加 --lowvram 参数启动。

日常更新只需要在项目目录里执行 git pull，然后重新 pip install -r requirements.txt；如果依赖有较大变动，删掉 venv 重新建一次更省事，模型目录不受影响。
