自定义 Skills

Skill 是给 CodeX 写的"专属能力说明书"——一个文件夹，里面放一份 SKILL.md，可选再放脚本和参考文档。CodeX 读了它，就知道"遇到什么情况该怎么做"。

CodeX 的 Skill 遵循 Agent Skills 开放标准，和 Claude Code 用的是同一套规范（SKILL.md + frontmatter），两边的 name / description 写法完全通用，方便互相迁移。差别在扩展字段上：Claude Code 额外支持 allowed-tools、disable-model-invocation 这类 frontmatter，CodeX 则把这些策略放到 agents/openai.yaml 里。

Skill 的存放位置

这是最需要注意的一点：CodeX 不用 .claude/skills/，而是扫描 .agents/skills/。

类型 路径 生效范围
项目级 ./.agents/skills/<name>/SKILL.md 当前仓库
全局 ~/.agents/skills/<name>/SKILL.md 你本机所有项目
企业级 /etc/codex/skills/<name>/SKILL.md 整台机器的所有用户
CodeX 会从当前工作目录一路向上扫描到仓库根，沿途每个目录下的 .agents/skills/ 都会被发现。所以在 monorepo 的子模块里放 Skill 也能生效，不需要提到根目录。

调用方式

方式 写法 说明
显式调用 $skill-name 最直接的方式，输入 $ 加 Skill 名
Skill 列表 /skills 查看当前可用全部 Skill
隐式调用 无需任何操作 CodeX 根据 description 自动判断该不该用

SKILL.md 最小结构 

---
name: skill-name
description: Explain exactly when this skill should and should not trigger.
---

Skill instructions for Codex to follow.

name 和 description 是必填字段，作用和 Claude Code 完全一致：name 是标识符，description 决定 CodeX 什么时候该自动加载这个 Skill。

description 里要同时写清楚"什么时候该用"和"什么时候不该用"。CodeX 官方模板明确建议这么写。比如：
description: Generate TypeScript types from OpenAPI definitions. Use when user says 'from swagger' or pastes an openapi.yaml. Do not use for runtime API calls or when generating REST clients.

一个实用示例：提交前自检 

---
name: pre-commit-check
description: Review uncommitted changes and flag risky edits before committing. Use when the user asks for a commit message, mentions committing, or asks 'what did I change'. Do not use for reviewing already-pushed commits.
---

## 当前改动
运行 git diff --stat 和 git diff HEAD，把结果作为上下文。

## 检查清单

按顺序检查并报告：

1. **错误处理**：新增的异步调用是否有对应的 error 分支
2. **硬编码值**：是否有密钥、URL、魔法数字直接写死
3. **测试同步**：改动是否需要同步更新测试用例
4. **命名规范**：是否遵循项目已有的命名约定

## 输出格式

- 用 2-3 条要点总结改动内容
- 然后单独列出风险项，每项标注文件路径和行号
- 如果没有发现风险，明确说"未发现明显风险"

控制是否允许自动触发

默认情况下 CodeX 可以隐式调用 Skill。如果某个 Skill 只应该在你明确要求时执行，可以在同目录放一个 agents/openai.yaml 声明策略： 

policy:
  allow_implicit_invocation: false
这个开关和 Claude Code 的 disable-model-invocation: true 是一回事，只是落点不同——CodeX 放在附加的 YAML 文件里，Claude Code 直接写在 SKILL.md 的 frontmatter。

禁用某个 Skill

在 ~/.codex/config.toml 里用 [[skills.config]] 关掉某个 Skill，不用删目录： 

[[skills.config]]
path = "/Users/you/.agents/skills/pre-commit-check/SKILL.md"
enabled = false
这里的键是 path（指向具体的 SKILL.md 文件路径），不是 Skill 名。改完要重启 CodeX 才会生效。

进阶技巧

组合多个 Skill

Skill 之间是可以叠加的。比如先跑 $pre-commit-check 确认改动没问题，再跑部署类的 Skill。可以一句话把顺序说清楚： 

先跑 $pre-commit-check 确认没有风险项，确认通过后再执行部署流程。

Skill 和 AGENTS.md 的分工

AGENTS.md Skill
加载时机 每次启动必读 被触发时才加载
适合放 事实：技术栈、构建命令、不可违反的约定 流程：操作步骤、检查清单、模板
成本 常驻占用上下文 几乎零成本，不用不加载

判断标准很简单：如果这段内容膨胀成了一份"操作步骤"，它就该搬到 Skill 里去。

目录结构建议 

.agents/skills/pre-commit-check/
├── SKILL.md          （必需）
├── CHECKLIST.md      （可选，展开的检查清单）
├── scripts/
│   └── diff-stats.sh （可选，脚本辅助）
└── templates/
    └── commit-msg.txt（可选，commit message 模板）

SKILL.md 正文建议控制在 500 行以内，超出部分挪到单独文件里按需引用。CodeX 只在需要时才读取这些辅助文件。

常见问题排查

现象 原因
CodeX 完全看不到这个 Skill 目录不是 .agents/skills/（最常见的错），或者 frontmatter 没写 --- 分隔符
$ 调用提示找不到 目录名和 frontmatter 的 name 不一致，两者必须完全相同
从不自动触发 description 太笼统，缺"当用户说 XXX 时使用"这类明确触发词
每次都触发，太吵 description 没写排除条件，或者没设 allow_implicit_invocation: false
排查第一步永远是 /skills：如果你的 Skill 不在这个列表里，说明根本没被加载，和 description 写得好不好无关。
