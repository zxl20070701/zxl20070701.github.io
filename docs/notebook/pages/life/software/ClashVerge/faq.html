常见问题与排错

这篇汇总用 Clash Verge 过程中最常遇到的问题，按「现象 → 原因 → 解决」的格式整理。遇到搞不定的问题，先看这篇，再去日志页看具体报错。

排错总原则

代理出问题，排查顺序永远是这四步：

  1. 连接页面：有没有流量进来？没进来 = 系统代理没开 / 流量根本没到 Clash
  2. 规则页面：流量命中了哪条规则？走的是 DIRECT 还是代理组？
  3. 日志页面：具体报了什么错？
  4. 测试页面：节点本身通不通？
「连接」页面是万能的第一现场。它是实时滚动的，能直接看到「哪个程序访问了哪个域名、走了哪个节点、命中哪条规则」。大部分问题看一眼这里就能定位。

装不上 / 装完打不开

现象 原因 解决
提示「此应用无法在你的电脑上运行」 下错架构了 换成对应你电脑的架构包，不确定就选 x64
提示缺少 VCRUNTIME140.dll 之类 系统没装 VC 运行库 装 Microsoft Visual C++ Redistributable 对应版本
双击没反应 / 闪退 / 只有托盘图标 WebView2 没装或被禁用 装 WebView2；或下 fixed_webview2 版本；检查是否被第三方软件禁用了 WebView2
macOS 提示「无法验证开发者」 未签名应用被 Gatekeeper 拦 系统设置 → 隐私与安全性 → 仍要打开；或执行 xattr -d com.apple.quarantine
Linux 提示缺 libwebkit2gtk 系统太老 Ubuntu 20.04 建议直接升级系统到 24.04

能连上但没网

现象一：关掉 Clash 就完全没网

这是系统代理没被正确关闭——软件退出了，但系统的代理开关还指着 127.0.0.1，流量全打到一个不存在的端口上。

解决：Windows 打开设置 → 网络和 Internet → 代理 → 手动设置代理，关掉「使用代理服务器」。

现象二：只有部分网站打不开

原因 解决
代理端口被别的程序占用（默认 7897） 设置页改端口，或关掉占用程序
游戏加速器等软件改过 hosts 文件 检查并清理 hosts：Windows 在 C:\Windows\System32\drivers\etc\hosts，Linux/macOS 在 /etc/hosts
规则把该网站判成了直连 规则页面看命中情况，加一条前置规则强制走代理
DNS 解析失败 开 DNS 模块；或用扩展脚本指定 nameserver

现象三：本地开发访问 localhost 报 502

本地请求被丢给节点了。加直连规则即可，详见上一篇《模式与规则分流》里的实战五。

公司内网访问不了

典型现象：内网域名打不开，但内网 IP 能打开。原因是开了 DNS 模块后，内网域名被交给公网 DNS 解析（公网当然查不到不公开的记录）。

解决：用扩展脚本给内网域名指定内网 DNS： 

function main(config) {
  config.dns = config.dns || {};
  config.dns["nameserver-policy"] = config.dns["nameserver-policy"] || {};
  config.dns["nameserver-policy"]["+.helloworld.com"] = "10.10.10.1";
  return config;
}

节点相关

现象 原因 解决
延迟测出来是 timeout，但网站能正常访问 杀毒软件（火绒等）的 HTTPS 扫描加密 关掉杀毒软件的 Web 扫描功能，或把软件目录加信任名单
所有节点都连不上 订阅过期 / 内核没跑起来 先更新订阅；再检查设置页内核版本；还不行就删配置目录重启
节点名称改了、还是旧的 订阅没更新成功 订阅卡片点刷新；还是不行就删配置目录重启
更新订阅报 401 链接失效 去后台重新复制链接

界面异常

现象 解决
代理页一片空白，但代理其实在跑 外部控制端口被占用。设置页「Clash 设置 → 外部控制」换一个监听端口，保存后重启
右上角小图钉不知道是干嘛的 红色=锁定且可用，灰色=锁定但不可用。点它可取消锁定
GPU 占用高 / 界面卡 设置 → 界面设置 → 关闭「流量图显」
Windows 更新后图标变成白方块 图标缓存没更新。Win+R 输入 cmd，粘贴 ie4uinit.exe -show 回车，或重启资源管理器
macOS 菜单栏图标重叠 macOS Sonoma 的系统 BUG，改一下分辨率再改回来

系统代理相关

Windows 应用商店（UWP）的应用不走代理

UWP 应用有沙盒限制，访问不了本机的 127.0.0.1。解决：设置页找到 UWP 工具，勾选要放行的应用，点顶部的 Save Changes。

宽带拨号连不上

Windows 宽带拨号有时不认系统代理。解决：删掉原有的宽带拨号连接，重新创建（连接名称不要用中文）。

macOS 系统代理开关点了没反应

改系统代理需要管理员密码，当前权限不够。解决：系统设置 → 隐私与安全性 → 高级 → 关闭「访问系统范围偏好设置需要输入管理员密码」。

TUN 模式的坑

TUN 模式会装虚拟网卡接管全部流量，比系统代理激进得多。能用系统代理就别开 TUN。真需要开时注意：

  • 需要管理员权限，Linux 下可能要装服务（设置页里有「服务模式」相关开关）
  • 开启后所有流量都进 Clash，包括内网，可能和公司 VPN 冲突
  • 有些杀毒软件会拦截 TUN 的网卡驱动，导致网断
  • 出问题时先关掉 TUN，用系统代理验证，排除是代理本身的问题还是 TUN 的问题

和 Watt Toolkit / steamcommunity 302 冲突

这类工具靠改 hosts 文件工作，而 Clash Verge 用的 Meta 内核默认会查询系统 hosts，两边打架就都访问不了被加速的站点。

解决：禁用内核查询系统 hosts。设置页新建「脚本」类型的扩展： 

function main(config) {
  config.dns = config.dns || {};
  config.dns["use-system-hosts"] = false;
  return config;
}
内核版本 ≥ v1.18.5 的话，也可以直接设系统环境变量 DISABLE_SYSTEM_HOSTS=1。实在解决不了，两个软件别同时用。

日志与数据

日志占满磁盘

设置里把日志等级调成 Silent 或 Error，并在杂项设置里开启自动清理日志间隔。

数据都在哪

系统 路径
Windows %APPDATA%\io.github.clash-verge-rev.clash-verge-rev\
macOS ~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev/
Linux ~/.local/share/io.github.clash-verge-rev.clash-verge-rev/

设置页右下角有个「配置目录」按钮可以直接打开这个位置。

删掉配置目录 = 重置所有设置，包括订阅、节点、规则。这是解决「配置乱掉了」最干净的办法，但会丢失所有自定义，先备份。

命令行里也想用代理

设置页选择「复制环境变量类型」（Bash / PowerShell / CMD），然后右键托盘图标 → 「复制环境变量」，粘贴到终端即可。 

export http_proxy=http://127.0.0.1:7897
export https_proxy=http://127.0.0.1:7897
export all_proxy=socks5://127.0.0.1:7897
复制出来的地址是 127.0.0.1 却连不上？加一个系统环境变量 CLASH_VERGE_REV_IP，值填你实际想用的 IP，重启软件再复制。

快速自查表

  • 系统代理开关已打开？（连接页面有流量吗）
  • 节点选好了吗？延迟是数字不是 timeout？
  • 模式是规则还是全局？
  • 规则页面上目标站点的规则命中数有增长吗？
  • 日志里有没有明显的 error 关键字？
  • 订阅是不是很久没更新了？
  • 试过把配置目录清空重启吗？
