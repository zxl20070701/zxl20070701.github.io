模式与规则分流

上一篇已经能用起来了。但默认的「规则」模式是机场下发的规则，不一定是针对你实际需求优化的。这篇讲清楚分流是怎么回事、怎么按自己的需求改，以及怎么用「扩展配置」加自己的规则。

分流到底在分什么

一句话解释：软件拿到每个网络请求后，拿它去比对一张「规则表」，命中哪条就走哪条路。 

你访问 example.com
   ↓
比对规则表（从上到下，命中即停）
   ↓
命中 "DOMAIN-SUFFIX,com,DIRECT"  →  直连，不走代理
命中 "MATCH,🚀 节点选择"            →  走代理

规则表通常长这样： 

rules:
  - GEOSITE,category-ads-all,REJECT      # 广告 → 直接拦截
  - GEOIP,CN,DIRECT                       # 中国 IP → 直连
  - GEOSITE,cn,DIRECT                     # 中国域名 → 直连
  - MATCH,🚀 节点选择                      # 其余全部 → 走代理
规则从上到下匹配，命中第一条就停止，后面的不再看。所以规则顺序直接决定结果，「把某网站加在最前面」就意味着「强制它走/不走代理」。

常用规则类型速查

类型 匹配什么 例子
DOMAIN 完全匹配的域名 DOMAIN,google.com,DIRECT
DOMAIN-SUFFIX 域名后缀（含子域） DOMAIN-SUFFIX,youtube.com,🚀 节点选择
DOMAIN-KEYWORD 域名里含关键词 DOMAIN-KEYWORD,ads,REJECT
GEOSITE 按地理站点库匹配（最常用） GEOSITE,cn,DIRECT、GEOSITE,youtube,📹 YouTube
GEOIP 按 IP 归属地匹配 GEOIP,CN,DIRECT
IP-CIDR IP 段 IP-CIDR,192.168.0.0/16,DIRECT
DST-PORT 目标端口 DST-PORT,22,DIRECT
PROCESS-NAME 程序进程名 PROCESS-NAME,WeChat.exe,DIRECT
REJECT 特殊值：直接拦截 GEOSITE,category-ads-all,REJECT
MATCH 特殊值：兜底，必须放最后 MATCH,🚀 节点选择
MATCH 是兜底规则，必须写在最后一条。放前面的话后面所有规则都永远不会生效，配置看起来"生效了"但完全不是你想要的效果。

改规则的三种入口

左侧分叉箭头图标（规则）页面可以看到当前生效的完整规则列表。想改规则有三条路，区别在于会不会被订阅更新冲掉：

方式 怎么改 订阅更新后
编辑规则 右键订阅卡片 → 编辑规则 → 填 prepend / append 保留，机场更新不会冲掉
扩展配置 订阅页新建「配置」类型，YAML 覆写 保留
扩展脚本 订阅页新建「脚本」类型，JavaScript 改配置 保留
直接改订阅 YAML 点订阅卡片的编辑按钮 会被冲掉，机场更新后你的修改就没了
记住这条原则：凡是自己的定制，都放在「编辑规则」/「扩展配置」/「扩展脚本」里，别直接改订阅原文。只有这三种方式能在订阅更新后存活。

方式一：编辑规则（最常用）

在订阅页面右键点击订阅卡片，选择「编辑规则」，可以填两个位置：

位置 含义 建议
prepend（前置规则） 插到订阅规则最前面，优先级最高 自定义规则放这里
append（后置规则） 插到订阅规则最后面（MATCH 之后其实已经不生效了） 基本不用

实战一：让某个网站直连

假设你用 DOMAIN-SUFFIX 让公司内网域名走直连： 

- DOMAIN-SUFFIX,mycompany.com,DIRECT
- DOMAIN-SUFFIX,intranet.local,DIRECT

实战二：屏蔽广告 

- GEOSITE,category-ads-all,REJECT
- DOMAIN-KEYWORD,ads,REJECT
- DOMAIN-KEYWORD,tracker,REJECT
广告规则用 REJECT 直接掐断，比走代理再丢弃省流量也省事。不过 用多了可能误伤，比如某些站点 URL 里就带 "ads" 字样却不是广告，出现页面空白时先怀疑它。

实战三：某个网站必须走代理

规则模式默认走代理，但如果某个国内网站被误判成直连导致打不开，就在最前面加一条强制走代理： 

- DOMAIN-SUFFIX,example.com,🚀 节点选择

这里的 🚀 节点选择 换成你订阅里真实存在的代理组名称。名称写错会导致规则匹配不到任何东西——去代理页面看一眼组名，注意带 emoji 和空格。

实战四：让某个程序走代理 

- PROCESS-NAME,Telegram.exe,📱 Telegram
- PROCESS-NAME,steam.exe,🎮 游戏加速
- PROCESS-NAME,WeChat.exe,DIRECT
PROCESS-NAME 规则依赖内核的进程匹配功能，部分版本/模式下可能不生效。不确定的话在「规则」页面看命中情况，或者改用域名规则。

方式二：扩展配置

扩展配置是一段 YAML，用来覆写订阅里的配置项，比如强制打开 DNS、开启 IPv6、调整并发数。

在订阅页面点「新建」→ 类型选「配置」，写好后右键卡片点「启用」。 

dns:
  enable: true
  ipv6: false
tcp-concurrent: true

合并规则（重要）

扩展配置只改你写了的字段，但不同类型字段的覆盖方式不一样，搞清楚能少踩很多坑：

字段类型 行为 例子
列表 / 普通值 整体替换 rules、dns.nameserver、tcp-concurrent
嵌套对象 逐项合并 tun、sniffer
dns 下的字段 + 顶层 hosts 整体替换（v2.5.5 起） 写 dns.nameserver 会把订阅原有的整个 nameserver 换掉
「整体替换」很容易出事。比如你只想加一条 nameserver-policy，结果把订阅原有的整张表换掉了，其他内网域名就解析不了了。要保留原有条目就得把原有的一起写上，或者改用扩展脚本追加。

哪些字段写了也没用

设置页里的选项优先级最高，这些字段由应用接管，扩展写了会在最后被丢弃并弹出提示： 

external-controller、external-controller-cors、secret
mixed-port、socks-port、port、redir-port、tproxy-port
mode、allow-lan、log-level、ipv6、unified-delay
tun.enable、stack、device、auto-route、mtu ...
想改端口、去设置页改；想在扩展里改 tun.stack 之类的，得去设置页的 TUN 对话框里改（保存过的字段会被应用接管）。这不是 bug，是防止配置互相打架的设计。

方式三：扩展脚本

当配置项写死满足不了需求，用 JavaScript 改最灵活。订阅页新建「脚本」类型，内容是一个 main(config) 函数： 

function main(config) {
  // 追加一条 nameserver-policy，保留订阅原有的
  config.dns = config.dns || {};
  config.dns["nameserver-policy"] = config.dns["nameserver-policy"] || {};
  config.dns["nameserver-policy"]["+.example.com"] = "https://1.1.1.1/dns-query";

  // 关掉查询系统 hosts
  config.dns["use-system-hosts"] = false;

  return config;
}

实战五：解决 localhost 被代理导致 502

这是新手最容易遇到的坑之一：本地开发时访问 localhost 报 502 / 连接被拒。原因是本地请求被当成普通流量丢给节点了，节点那边根本没有你的服务。

解决办法是让 localhost 走直连。在订阅卡片的「编辑规则」→ prepend 里加： 

- DOMAIN-SUFFIX,localhost,DIRECT
- IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
- IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
- IP-CIDR,172.16.0.0/12,DIRECT,no-resolve
- IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
no-resolve 一定要加，表示匹配 IP 段时不要反查域名，能避免额外 DNS 请求和延迟。

实战六：让内网域名走内网 DNS

公司内网域名用公网 DNS 解析不出来（本来就不对公网公开）。在扩展脚本里指定内网 DNS： 

function main(config) {
  config.dns = config.dns || {};
  config.dns["nameserver-policy"] = config.dns["nameserver-policy"] || {};
  config.dns["nameserver-policy"]["+.helloworld.com"] = "10.10.10.1";
  return config;
}

假设你的内网 IP 是 10.10.10.123，网关是 10.10.10.1，要访问的域名是 www.helloworld.com。

排查规则有没有生效

改了规则不确定对不对，规则页面每一行右侧都有「命中次数」。改完访问一次目标网站，回来看看对应规则的命中数涨了没：

  • 命中数涨了 → 规则生效
  • 命中数是 0 → 域名写错了、位置不对、或者被前面的规则抢先命中了

另一个更直接的办法是看「连接」页面：每条连接的「规则」列会显示它命中了哪条规则，一目了然。

还可以在日志页把日志等级调到 debug，能看到完整的匹配过程。查完记得调回 warn 或 error，debug 日志涨得很快。

一份实用规则模板

新手可以直接照抄这个思路（放在订阅卡片的编辑规则 → prepend）： 

# —— 本地与内网直连 ——
- DOMAIN-SUFFIX,localhost,DIRECT
- IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
- IP-CIDR,192.168.0.0/16,DIRECT,no-resolve

# —— 广告拦截 ——
- GEOSITE,category-ads-all,REJECT

# —— 必须走代理的网站 ——
- DOMAIN-SUFFIX,youtube.com,🚀 节点选择

# —— 剩下的交给订阅自带的规则 ——
记住核心原则：定制放前置、用 GEOIP/GEOSITE 做粗粒度判断、用 DOMAIN 规则处理特例。规则不是越多越好，够用就行。
