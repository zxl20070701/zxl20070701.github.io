兼容OpenAI API

Claude Code 原生走的是 Anthropic 协议（POST /v1/messages），而很多国产模型、本地 Ollama、Moonshot、豆包、DeepSeek 等只提供 OpenAI 协议（POST /v1/chat/completions）。两边的字段、流式格式、tool call 结构都不一样，直接把 OpenAI 兼容地址塞进 cc-switch 的 -u 参数，大概率会报 400 校验错误。

解决办法很简单：在 Claude Code 和上游之间起一个零依赖的本地协议网关 llm-api-io。网关只做一件事——"上游一种协议，本地同时暴露两种协议"，这样 Claude Code 继续发 Anthropic 请求，网关自动帮你转换成上游需要的 OpenAI 请求，再把返回结果转回 Anthropic 格式给 Claude Code。

整体链路 

Claude Code (Anthropic /v1/messages)
   │
   ▼
本地 llm-api-io（默认 127.0.0.1:8001）
   │  自动做 Anthropic ↔ OpenAI 协议转换
   ▼
上游 OpenAI 兼容服务（Ollama / Moonshot / 豆包 / DeepSeek …）

安装 llm-api-io

推荐全局安装一次，之后任意终端都能直接用： 

npm install -g llm-api-io

也可以不装，直接 npx 跑一次就启动： 

npx llm-api-io --help
llm-api-io 零依赖，不挑 Node 版本。如果 npx 报找不到包，先确认当前 npm registry 可达，或者显式带上 registry：npx --registry=https://registry.npmmirror.com llm-api-io --help。

最小组合拳

假设你本地 Ollama 跑在 http://localhost:11434，有一个 qwen3.5 模型。

1. 起本地网关

告诉 llm-api-io"上游是 OpenAI 协议"，然后在本机开一个默认 8001 端口的双向入口： 

llm-api-io --openai-url http://localhost:11434 --port 8001

终端会持续监听，不要关闭，保持这个窗口挂着即可。

2. 让 Claude Code 指向本地网关

用 cc-switch 新增一套配置。注意 URL 指向 http://localhost:8001（不要带 /v1，网关会自动拼），模型名写你上游真实存在的那个。 

cc-switch add local -t sk-local -u http://localhost:8001 -m qwen3.5
cc-switch use local

现在正常执行 claude，Claude Code 发给 Anthropic 协议的请求会由 llm-api-io 自动转成 OpenAI 请求送进 Ollama，流式、tool call、图片都已覆盖。

如果不需要 cc-switch 这种多配置切换工具，直接在 ~/.claude/settings.json 里写 "env": { "ANTHROPIC_BASE_URL": "http://localhost:8001", "ANTHROPIC_AUTH_TOKEN": "sk-local" } 也是一样的。环境变量方式更稳，避免明文把 key 写进命令行。

路由与协议关系

llm-api-io 会根据请求路径自动判断该走哪条转换链路：

本地入口 上游 OpenAI 上游 Anthropic
POST /v1/chat/completions 原样直通 OpenAI → Anthropic 转换
POST /v1/messages Anthropic → OpenAI 转换 原样直通

对 Claude Code 来说，它只会命中第二行的 /v1/messages，所以上面的组合拳里，Claude Code → 网关 → 上游 OpenAI 的方向已经完全覆盖。

进阶参数

统一覆盖上游密钥

直接在命令行传 --api-key，网关会用这个 key 覆盖所有客户端传入的 Authorization，适合上游只认固定凭证的场景： 

llm-api-io --openai-url https://api.deepseek.com --api-key sk-xxxxxx --port 8001

不写 --api-key 时，网关默认透传客户端的密钥——也就是 Claude Code 侧填的 ANTHROPIC_AUTH_TOKEN，会原样带到上游 OpenAI 的 Authorization 头里。两种方式根据上游鉴权策略选。

强制指定上游模型

有些场景希望不管 Claude Code 传入什么 model 字段，都打到上游固定模型上，直接用 --model： 

llm-api-io --openai-url http://localhost:11434 --model qwen3.5 --port 8001

更常见的是模型名映射：Claude Code 侧习惯写 claude-sonnet，上游其实叫 qwen3.5，用 --model-map 改一下： 

llm-api-io --openai-url http://localhost:11434 \
    --model-map claude-sonnet=qwen3.5 \
    --model-map claude-opus=qwen3.5 \
    --port 8001

可以多次传，也可以写成逗号分隔：--model-map a=b,c=d。

端口、地址、超时 

llm-api-io --openai-url http://localhost:11434 \
    --host 0.0.0.0 --port 8001 \
    --timeout 600000 --verbose

默认监听 127.0.0.1:8001，如果要让同网段其他机器也能用，显式加上 --host 0.0.0.0。上游超时默认 10 分钟，长对话可以按需调大。加 --verbose 会打印每条请求的协议方向、目标路径、模型名、耗时和转换告警，排查字段兼容问题时先看这些日志。

关于 max_tokens 兜底

Anthropic 协议要求请求里必须传 max_tokens，但 Claude Code 有时候不把这个字段给 llm-api-io。网关会自动补上一个兜底值，默认是 4096。想改就加 --max-tokens： 

llm-api-io --openai-url http://localhost:11434 --max-tokens 8192 --port 8001

关于 CLAUDE_CODE_SIMPLE

有些 OpenAI 兼容模型对 messages 数组的 role 校验非常严格，只允许 user / assistant，不认 Claude Code 新版会直接塞进去的 system 角色，然后返回 400 校验错误。

如果遇到这种报错，在 ~/.claude/settings.json 的顶层 env 节点加上： 

{
  "env": {
    "CLAUDE_CODE_SIMPLE": "1"
  }
}

保存后彻底重启 Claude Code。这条 workaround 是 Claude Code 侧的，不是 llm-api-io 网关的；llm-api-io 本身已经负责协议转换，role 问题主要出现在上游模型的校验策略上。
