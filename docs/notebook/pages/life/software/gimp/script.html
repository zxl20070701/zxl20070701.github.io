脚本与批处理

这是 GIMP 相对 Photoshop 最大的优势：内置 Python-Fu 解释器，可以写脚本直接操作 PDB 命令，做真正的无人值守批处理。PS 的「动作」只能机械回放，而 GIMP 脚本可以读文件、判断尺寸、按条件分支。

两种脚本语言

语言 特点
Python-Fu Python 2.7 语法（GIMP 3.0 起支持 Python 3）。推荐首选，生态丰富、可读性强
Script-Fu TinyScheme 方言，Lisp 风格。老脚本多是这套，无需额外依赖
其它 3.0 起还支持 JavaScript 等更多语言

控制台

过滤器 → Python-Fu → 控制台（或 Script-Fu → 控制台），这是最快的上手方式： 

# 打开控制台后可以逐行执行
img = pdb.gimp_file_load('/path/to/a.jpg', 'a.jpg')
print(img.width, img.height)   # 打印图片尺寸
控制台是边试边改的工具：写一行跑一行，出错信息直接看到。脚本写完再粘到文件里跑，比一上来就保存执行文件调试快得多。

PDB 基础

所有脚本操作都基于 PDB（Procedure Database）。三个核心概念：

  • image：图像，脚本里的所有操作都挂在某个 image 上
  • drawable：可绘制对象，图层、通道、选区都算
  • 返回值句柄：pdb 函数返回的是整数句柄，后续调用要传回去

常用命令速查 

# 文件操作
img = pdb.gimp_file_load(path, name)            # 加载图片
img = pdb.gimp_image_new(w, h, 0)              # 新建图片
pdb.gimp_image_insert_layer(img, layer, 0, -1) # 插入图层
pdb.gimp_layer_new_from_drawable(...)          # 从现有对象创建图层

# 缩放
pdb.gimp_image_scale(img, w, h)                # 整图缩放
pdb.gimp_layer_scale(l, w, h, FALSE)           # 图层缩放

# 导出
pdb.file_png_save(img, drawable, path, path, 0, 9, 1, 1, 1, 1, 1)
pdb.file_jpeg_save(img, drawable, path, path, 0, 0.9, 0.0, 1)
pdb.gimp_image_delete(img)                     # 清理

# 效果
pdb.gimp_brightness_contrast(layer, 0, 30)
pdb.gimp_gaussian_blur(layer, 5, 1, 0)

查命令用 帮助 → 搜索和运行一个 PDB 过程，能看到每个命令的参数说明。不确定参数时别猜，这里一查就有。

3.2.6 起 PDB 命令在非交互模式下不再往控制台刷错误信息。所以写批处理脚本时，一定要检查返回值，不要指望控制台给你报错。

第一个脚本：批量改尺寸

把它存成 ~/.config/GIMP/3.2/scripts/resize.py，重启 GIMP 后在 过滤器 → Python-Fu → resize 里就能找到。 

import os

def batch_resize(folder, out_folder, max_width=1200, quality=0.9):
    if not os.path.exists(out_folder):
        os.makedirs(out_folder)

    for name in os.listdir(folder):
        if not name.lower().endswith(('.jpg', '.jpeg', '.png')):
            continue

        src = os.path.join(folder, name)
        img = pdb.gimp_file_load(src, name)

        # 等比缩小
        w = img.width
        h = img.height
        if w > max_width:
            ratio = float(max_width) / w
            pdb.gimp_image_scale(img, max_width, int(h * ratio))

        # 拉平成一层再导出，避免透明区域变黑
        flat = pdb.gimp_image_flatten(img)

        dst = os.path.join(out_folder, name)
        if dst.lower().endswith('.png'):
            pdb.file_png_save(img, flat, dst, dst, 0, 9, 1, 1, 1, 1, 1)
        else:
            pdb.file_jpeg_save(img, flat, dst, dst, 0, quality, 0.0, 1)

        pdb.gimp_image_delete(img)
        print('done: ' + name)
一定要调 gimp_image_delete。不删的话图片会留在内存里，处理几百张就会把 GIMP 撑爆。这是新手写批处理脚本最常见的错误。

插件注册

想要脚本出现在菜单里，需要加注册代码。脚本主体和注册代码要分开，否则 GIMP 加载时会把主体也执行一遍： 

# ---- 主体逻辑 ----
def batch_resize(folder, out_folder, max_width):
    # ... 上面那些代码 ...
    pass


# ---- 注册 ----
def run():
    folder = '/path/to/input'
    out_folder = '/path/to/output'
    batch_resize(folder, out_folder, 1200)


register = {
    "name": "批量缩放",
    "blurb": "批量缩放指定目录的图片",
    "author": "you",
    "version": "1.0",
    "menu_path": "<Image>/File/",
    "icon": None,
    "run": run,
}

register_plugin("python-fu", register)

menu_path 的取值

写法 位置
<Image> 只有打开图片后才出现
<Tools> 工具菜单
<File> 总是出现

路径用 / 连接子菜单。比如 <Image>/Filters/ 会出现在图像菜单的 Filters 子菜单里。

命令行批处理

不想开 GUI 批处理时，用 gimp -i -b 无头模式。相关参数：

参数 作用
-i 无界面运行，批处理必备
-b 执行批处理命令，- 表示从标准输入读
--batch-interpreter 指定解释器，默认 Script-Fu，用 Python 传 python-fu-eval
--quit 执行完立即退出
-d 不加载笔刷、图案等，加快启动
-c 错误输出到控制台，不弹对话框 
# 用 Script-Fu 合并两张图并导出
gimp -i -b '(gimp-message "hello")' -b '(gimp-quit 0)'

# 从文件读脚本（推荐，可读性好）
gimp -i --batch-interpreter=python-fu-eval -b "$(cat script.py)" --quit

# 批量转换某个目录（配合 shell）
for f in *.jpg; do
    gimp -i -b "(gimp-file-load RUN-NONINTERACTIVE \"$f\" \"$f\")" \
            -b "(gimp-file-save RUN-NONINTERACTIVE 1 \"$f\" \"${f%.jpg}.png\" \"${f%.jpg}.png\")" \
            -b "(gimp-quit 0)"
done
批处理第一件事永远是加 -c 和 --quit。少了 --quit，GIMP 会挂在那里等；少了 -c，出错时会弹一个没人点的对话框，整个流程卡死。

Script-Fu 快速示例

如果现成脚本用的是 Script-Fu（很多网上流传的脚本都是），先掌握这几个函数： 

(let* ((img (car (gimp-file-load RUN-NONINTERACTIVE path path)))
       (drawable (car (gimp-image-flatten img))))
  (gimp-file-save RUN-NONINTERACTIVE img drawable out out out)
  (gimp-image-delete img))

Script-Fu 的特点：返回值都是列表，要 car 取第一个元素；RUN-NONINTERACTIVE 是批处理必需的第二个参数。括号必须配平，报错信息通常只指出位置不指出原因。

优先用 Python-Fu。Script-Fu 的括号地狱和静默失败会浪费大量调试时间，老脚本看不懂时可以直接按文档重写成 Python。

文件路径约定

  • Linux：~/.config/GIMP/3.2/scripts/
  • Windows：%APPDATA%\GIMP\3.2\scripts\
  • macOS：~/Library/Application Support/GIMP/3.2/scripts/

放进去后必须重启 GIMP才会重新扫描脚本目录。

常见问题排查

脚本没出现在菜单里

三个可能：文件没放到正确的 scripts 目录、注册代码格式错误（register_plugin 那几行必须在）、没重启 GIMP。

处理几十张图片后崩溃 / 内存爆掉

99% 是漏了 pdb.gimp_image_delete(img)。每张处理完立刻删掉引用。

导出的图和预览不一样

GIMP 里显示的是合成结果，导出的是按图层混合计算的。常见原因是有图层处于隐藏或半透明状态。用 gimp_image_flatten 拉平后再导出，导出结果就等于你看到的。

透明区域导出后变黑

直接导出会把透明像素的 RGB 分量（通常是黑色）带出来，某些查看器按黑色显示。修法：先 gimp_image_flatten，或导出时指定合适的背景色。

脚本报「找不到过程」

命令名拼错，或该命令在新版本改名了。用 帮助 → 搜索和运行一个 PDB 过程 搜索确认。注意 GIMP 3.0 移除了一些 2.x 的旧命令。

批处理卡住不动

缺 -c 参数导致弹了模态对话框。加上 -c 让错误走控制台，或在脚本里用 pdb.gimp_progress_init / gimp_progress_update 加进度反馈。

脚本执行到一半图不见了

除了漏 delete，另一个原因是用变量持有句柄但没有引用图像。GIMP 的垃圾回收基于引用计数，没有引用的对象会被立刻释放。所以一定要 img = pdb.gimp_file_load(...) 赋给变量保持引用。
